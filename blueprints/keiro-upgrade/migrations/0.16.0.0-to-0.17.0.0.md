# Keiro 0.16.0.0 → 0.17.0.0

This edge covers native read-model query fencing and additional public error
cases. The external dependency cohort, migrations and DSL language are unchanged;
no upstream edge is entailed.

## Precondition

Apply when the consumer uses native read-model queries or exhaustively matches
`ReadModelError`. Align consumed Keiro packages to the 0.17.0.0 lockstep set
and preserve external dependency bounds. Earlier consumers must also cross the
prior version edges; this edge does not replace the 0.15.0.0 timer-writer rollout.

## Preserve honest query failure

Handle `ReadModelGroupUnavailable` and `ReadModelRegistrationChanged` in exhaustive
error matches. Group rebuilding/unavailability and a registration changed during
lock acquisition are refusal outcomes, not empty data or permission. Retry only
under the consumer's bounded freshness/deadline policy, obtaining fresh metadata.
Native queries hold ordered group/model locks through SQL and revalidate after
waits, so keep transactions bounded and avoid unrelated work inside them.

For a compound observation, use `ReadModelRequirement`, `readModelRequirement`
and `runReadModelTransaction` to cover every participating native model in one
transaction. Do not split validated metadata reads from later SQL or bypass the
owning query API with unguarded reads. Test concurrent rebuild/cutover against
actual PostgreSQL and preserve explicit refusal rather than fabricating evidence.

## Optional terminal outbox replay

`replayDeadOutbox` makes one dead row claimable when its attempt count still
matches the inspected value. It preserves spent attempts and the original
message; normal publisher policy and recipient authorization govern delivery.
Do not automatically refresh the expected count after refusal or reset it with
SQL. Sent, rejected and nonterminal records remain unchanged. This is an optional
new operation, not a requirement to replay existing dead deliveries on upgrade.

## Validate

Run the consumer's build, exhaustive error tests and PostgreSQL query/rebuild
concurrency tests. Run its receipt/identity and stale-replay tests if adopting
terminal replay. Keiro validates this release with `just verify` and
`nix flake check`; the owning suites include native query fencing, versioned
rebuilds and outbox replay/refusal/rollback. No database rewrite or generated DSL
edition change is required for this edge.
