# Keiro 0.16.0.0 → 0.17.0.0

This edge covers required source adaptations for declared work-queue ordering, guarded dead-letter
operations, deterministic producer outbox identity, and changed public record surfaces. The
upstream Kiroku, Keiki, and Shibuya cohort is unchanged, so no upstream edge is entailed. The pgmq
package family and its Shibuya adapter move together as ordinary dependency updates.

## Precondition

Apply this edge when the project depends on any Keiro package. Each step states which package or
surface makes it applicable. Report an inapplicable step as not applicable and continue; do not
exit nonzero merely because the project does not use that surface. Start from a clean working tree
and identify work-queue `Job` values, explicit `JobTuning`, DLQ operations, canonical outbox
producers, direct `KeiroMetrics` construction, and generated DSL service fills before editing.

## Step 1 — Align dependencies

Update every Keiro package the project consumes to the 0.17.0.0 lockstep set. If the project names
the pgmq packages directly, move `pgmq-config`, `pgmq-core`, `pgmq-effectful`, `pgmq-hasql`, and
test-only `pgmq-migration` to `>=0.6 && <0.7`. Move `shibuya-pgmq-adapter` to
`^>=0.16.0.0`. Keep `kiroku-store >=0.8 && <0.9`, `kiroku-store-migrations ^>=0.4.0.0`,
`keiki >=0.9 && <0.10`, and `shibuya-core ^>=0.9.0.0` unchanged. Report solver conflicts rather
than adding `allow-newer`, source-repository overrides, or unreviewed pins.

Before adopting grouped-head FIFO delivery, confirm that the deployed PGMQ extension is 1.12 or
later. Other ordering strategies do not add that server requirement.

## Step 2 — Adapt work queues and dead-letter operations

For projects that consume `keiro-pgmq`, add `jobOrdering` to every `Job` record. Use `Unordered`
for existing unordered jobs. Make every explicit `JobTuning.ordering` match the declaration, or
derive defaults with `withOrdering job.jobOrdering defaultJobTuning`. A mismatch now throws
`JobConsumptionConfigError`. `FifoThroughput` and `FifoRoundRobin` remain single-message legacy
strategies and reject `batchSize > 1`; use batch size one or adopt `FifoHeads` after confirming the
server requirement. `FifoHeads` batches one visible head per group while preserving strict order
inside each group.

Update exhaustive construction or positional matching of the re-exported `QueueMetrics` record for
its nullable `defaultPartitionLength` field. Update exhaustive `DlqEntry` construction or matching
for `originalHeaders`; redrive now republishes the original wrapper headers rather than the DLQ
row's transport headers.

`purgeDlq` now returns `PurgeDlqResult`. Handle `PurgeDlqPurged count` and
`PurgeDlqBlocked hiddenCount` explicitly. Inspection through `readDlq`, redrive, or archive can hide
rows, and guarded purge refuses while any such rows exist. Use `archiveDlqEntries` to archive the
specific inspected IDs. Use `purgeDlqForce` only where unconditional deletion is the reviewed
operator intent. The `keiro-ops pgmq dlq purge --force` command also uses the guarded API and exits
without deleting when rows are hidden.

## Step 3 — Adapt canonical outbox producers

For projects using `IntegrationProducer`, rewrite `enqueueProducerEventTx` calls to pass the
persisted `RecordedEvent` and a `Word32` emission index. Use index `0` only when one mapper emits one
draft per source event; otherwise assign a stable index to each emission. The transaction now
returns `ProducerInserted`, `ProducerDuplicateIdentical`, or `ProducerIdentityConflict`. Condemn
the checkpoint transaction on identity conflict, and call `recordProducerEnqueueOutcome` once
after the runner returns.

The producer now derives both IDs from the source, producer name, source event ID, and emission
index. Message IDs are opaque `<namespace>_v1_<sha256-hex>` text rather than TypeIDs. Drain old
in-flight attempts, keep the committed source checkpoint, and do not replay pre-cutover history
under the new derivation without an application-owned mapping. Keep source, producer name,
namespace, and emission-index assignments stable after cutover.

Replace `mintIntegrationEvent` with `freshIntegrationEvent` only where the application truly wants
a fresh envelope unrelated to a recorded source event. Supply `outboxIdentityConflict` in direct
`KeiroMetrics` construction. `Keiro.Outbox` now re-exports `Keiro.Outbox.Identity`; qualify or use
record-dot syntax for bare `outboxId`, `messageId`, or `sourceEventId` selector calls that become
ambiguous. `mkIntegrationProducer` rejects an empty message-ID namespace.

## Step 4 — Review process-manager and inbox adoption

`Keiro.ProcessManager.Reaction`, transactional timer cancellation, and delegated inbox wrappers are
additive. Existing users need no source change. Do not switch an existing manager name to the
reaction runner without draining the old runner and reviewing its persisted identity contract.
Delegated inbox intake is opt-in and moves receipt ownership to the downstream event boundary.

## Step 5 — Adapt DSL consumers

For projects that consume `keiro-dsl`, add
`jobOrdering = QueuePolicy.jobOrdering` to every hand-owned `WorkqueueJob` record fill. On the first
re-scaffold, accept and commit the one-time `process-reaction` ledger rows with
`verification = "custom-unverified"` for legacy processes. Check-report JSON under schema
`keiro-dsl/check-report/1` now includes the `processReactions` key, so update strict report decoders
or golden files.

`ordering fifo-heads` belongs to the Language 6 candidate. A Language 4 or 5 spec must retain a
legacy ordering with batch size one; raise the source declaration to Language 6 only after adopting
the candidate contract. Language 6 also gained opt-in nominal IDs and enums across structural
mapped surfaces, declared IDs in contracts, nested nominal expressions, and identifier-keyed maps.
Those additions require no migration for existing Language 1 through 5 specs.

Do not hand-edit generated output. Re-scaffold from the source specification and commit the source,
hand-owned fills, ledger, and generated changes together.

## Validate

Run the consumer's normal build and tests. If grouped-head FIFO was adopted, run an integration test
against the deployed PGMQ 1.12-or-later server. Exercise guarded purge after inspection and confirm
the blocked result is handled without deletion. Exercise canonical producer replay and prove an
identical source event is reported as a duplicate while changed content is rejected as an identity
conflict.

This repository uses `cabal build all`, `just verify`, and `nix flake check` as the reference gates.
Do not add `allow-newer`, hand-edit generated files, mutate Keiro tables with ad hoc SQL, or
automatically translate historical random message IDs into the new deterministic identity.
