# Keiro 0.23.0.0 → 0.24.0.0

## Precondition

The consumer resolves Keiro 0.24.0.0 and previously used 0.23.0.0. Keep the
eight published Keiro packages aligned. Inspect its projection inspection
callers, embedded operational hooks, command matches and JSON fixtures. Report
unused surfaces as inapplicable without inventing work.

## Projection status page items

`ProjectionStatusPage.items` changes from `[ProjectionGroupStatusV1]` to
`[ProjectionGroupStatusRow]`. Read the frozen v1 fields through each item's
`status` field, for example `row.status.groupId` instead of `row.groupId`.
Construct the wrapper with `status` and `feedingSubscriptions` in owned fixtures;
use the registered subscription names, sorted, and an empty list for inline-only
or unmanaged groups. Do not infer subscription names from projection identifiers.

`projectionGroupStatusJson` continues to encode the frozen v1 record. For the
bounded page wrapper use `projectionGroupStatusRowJson`, which adds the flat
`feeding_subscriptions` array. The CLI `projection status --json`, HTTP
`/projection/status` and `projection_groups` feed share this shape. Adjust exact
JSON fixtures or closed decoders to accept the array; retain all existing fields.
Complete-list and lookup APIs and the frozen SQL relation retain their types
and contracts. Do not rewrite that SQL relation or historical migrations.

## Application hooks and command matches

`AppHooks` gains `durableConsumers :: Maybe DurableConsumerRegistry`. Prefer
updating `emptyAppHooks`; direct record constructors must supply the new field.
Use `Nothing` when durable-consumer metadata is not mounted. If mounting it,
construct a validated registry with `durableConsumerRegistry` from the same
configuration used by workers. Do not invent metadata from journal categories
or claim complete coverage for hooks that are absent.

Exhaustive matches on `Keiro.Ops.Projection.Command` must handle the new
`Consumers ConsumersOptions` constructor. Exhaustive matches on
`Keiro.Ops.Workflow.InspectionCommand` must handle `InspectCounts
WorkflowCountsQuery`. Both are read-only commands; preserve the consumer's
authorization, deadline and response-budget policies when dispatching them.

## Cohort, fixtures and generated services

The upstream dependency cohort and composed migration plan remain those of
0.23.0.0. No upstream edge is entailed. There is no database ledger fixup and
no required DSL service regeneration beyond the consumer's existing version and
provenance workflow. Preserve Language 5 stable and Language 6 candidate policy.
Do not drop persistent databases, alter checksums, overwrite application holes,
enable candidate features or add `allow-newer` as part of this upgrade.
