# Keiro 0.25.1.0 → 0.26.0.0

## Precondition

The consumer resolves Keiro 0.26.0.0 and previously used 0.25.0.0 or 0.25.1.0.
Keep the eight published Keiro packages aligned. Inspect the consumer's embedded
operational hooks and HTTP host options, its matches on `Keiro.Ops.Command`, and
any code that imports the `keiro-dsl` library (`Keiro.Dsl.Grammar`,
`Keiro.Dsl.DiffReport`, diagnostic and language-feature matches). Report unused
surfaces as not applicable. Do not invent work for them.

## Operational hooks and HTTP hosts

- `Keiro.Ops.AppHooks` gains `serviceTopology :: Maybe ServiceTopologyDocument`.
  Prefer a record update of `emptyAppHooks`. Direct record constructors must
  supply the field: `Nothing` keeps the previous behavior. Mount a document only
  when the project already commits a keiro-dsl topology file. Load it with
  `loadServiceTopology` and do not hand-write one.
- `Keiro.Ops.Command` gains `Topology Topology.Command`. Exhaustive matches must
  handle it. Both `topology show` and `topology summary` are reads, so give them
  the same authorization, deadline and response-budget policy as other read
  commands.
- `Keiro.Ops.Http.Host.HostOptions` gains `topology :: Maybe FilePath`. Code that
  constructs `HostOptions` must set it, usually to `Nothing`. `--topology FILE`
  on a `mainWithHooks` host overrides any document mounted in code.

## keiro-dsl library consumers

This section applies only to code that imports the `keiro-dsl` library. It does
not apply to code that generates services with the CLI.

- `ContractType` gains `COptional`. `ContractNode.discriminator` changes from
  `Name` to `ContractDiscriminator` (`DiscriminatorBodyKey name` or
  `DiscriminatorEnvelope`). Use `contractBodyDiscriminator` where a body key
  name was read directly, and handle the envelope case explicitly. Do not
  default it to a made-up key.
- `InputDecl` gains `source :: Maybe InputSource`. Constructors supply
  `Nothing`.
- Exhaustive matches must handle the new constructors:
  - `DiagnosticCode`: `ContractOptionalFieldAdded`,
    `ContractOptionalFieldUsedAsKey`, `InputSourceUnresolvedIntake`,
    `InputSourceEventNotAccepted`.
  - `LanguageFeature`: `ContractOptionalFieldSyntax`,
    `ContractEnvelopeDiscriminatorSyntax`, `InputSourceSyntax`.
  - `Keiro.Dsl.DiffReport.Remedy`: `RemedyDeployKeyWritersFirst`,
    `RemedyDrainBeforeStricterReader`.

## Generated services, cohort and database

Generated modules for existing `.keiro` sources are byte-identical apart from
the provenance version stamp. Regenerate with the matching 0.26 toolchain and
the project's existing scaffold command, preserving application holes. A
behavior-contract service also gets a rewritten `BehaviorContract.hs`, facade
and runner `Main.hs` that support the opt-in `--behavior-complete` flag. The
default runner output is unchanged.

Do not enable candidate Language 6 features (Optional contract fields,
`discriminator from envelope`, input sources) as part of this upgrade. Do not
start committing a topology file unless the project asks for it. The upstream
cohort, adapter requirements and the 50-migration framework plan are those of
0.25.0.0. There is no migration, checksum or ledger fixup. Do not drop
persistent databases or add `allow-newer`.

## Validation

Use the consumer's development shell to build with exhaustive-pattern checks
and run its tests, including any mounted operational routes. In this repository
the proving commands are:

```sh
nix develop -c z3 --version
nix develop -c cabal build all --enable-tests --enable-benchmarks
nix develop -c cabal test keiro-ops-test keiro-ops-http-test keiro-dsl:tests --test-show-details=direct
nix develop -c just release-gate
nix flake check
```

Report the resolved versions, the source adaptations, the regeneration results
and any validation that could not run.
