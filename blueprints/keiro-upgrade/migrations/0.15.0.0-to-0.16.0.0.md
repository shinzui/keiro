# Keiro 0.15.0.0 → 0.16.0.0

This edge covers migration 0032 and coordinated timer writer rollout. The
upstream dependency cohort is unchanged, so no upstream edge is entailed.
Existing timer row, callback, and ID-only function signatures remain compatible.

## Precondition

Apply this edge when the project uses Keiro timers or manages the Keiro database
schema. Otherwise report it not applicable. Start from a clean working tree and
identify every timer-mutating process, including background workers and custom
SQL writers, before planning deployment.

## Align dependencies and rollout

Update every Keiro package the project consumes to the 0.16.0.0 lockstep set.
Preserve external dependency bounds. Report solver conflicts rather than adding
unsupported overrides.

Stop or drain all old timer writers. Apply the normal `keiro-migrate up`
migration flow, including 0032, which adds paired nullable `resume_claim_token`
and `resume_lease_until` columns constrained to Firing rows. Deploy all upgraded
writers before enabling foreground resume. Mixed-version writers are unsafe:
older binaries do not enforce ownership exclusions. Review custom SQL mutations
for the same exclusions; do not bypass the public guarded API with direct SQL.

## Adapt recovery and foreground work

`TimerWorkerOptions.requeueStuckAfter = Nothing` now disables only ordinary
requeueing: every worker pass calls `recoverExpiredTimerResumes`. Expired guarded
claims return directly to Dead, retaining attempts and reasons. Update any
application assumptions or assertions that this option disables all recovery.
ID-only mark-fired, cancel, dead-letter, and requeue operations refuse guarded
claims, including expired ones awaiting recovery.

If adopting foreground resume, authorize and validate the original payload and
session before `claimDeadTimer`. Supply exact owner/reason guards, an explicit
total attempt ceiling, and a bounded lease. Execute only after receiving a claim;
use `renewTimerResume`, `completeTimerResume`, `parkTimerResume`, and
`cancelTimerResume` with that opaque handle. On lost ownership, stop local work
where possible and do not report successful completion. Foreground-only hosts
must periodically call `recoverExpiredTimerResumes` and do so before discovery.
External execution remains at-least-once: keep consumer-owned durable
idempotency and never infer authorization from stored owner or reason text.

Before rolling back writers, disable foreground resume and drain or recover all
guarded claims. Do not drop databases, rewrite migration history, clear claims
with ad hoc SQL, reset attempt counts, or raise ceilings automatically.

## Validate

Run the consumer's normal build and tests, including timer recovery and ownership
tests. Rehearse the ordered rollout on a disposable or restored database. This
repository validates the behavior and migration with `just verify`, including
`keiro-test` and `keiro-migrations-test`, and validates packaging/formatting with
`nix flake check`. Confirm ordinary workers cannot execute guarded work and that
expiry returns it to Dead without losing the original reason or retry history.
No DSL language or generated-edition migration is required by this edge.
