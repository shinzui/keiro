# Keiro 0.22.0.0 → 0.23.0.0

## Precondition

The consumer resolves Keiro 0.23.0.0 and previously used 0.22.0.0. Keep all
eight published Keiro packages aligned. Inspect direct Kiroku integrations,
custom interpreters and observers, migration fixtures, and owned databases.
Report unused surfaces as inapplicable without inventing adaptations. Use Mori
to locate dependency sources and inspect the consumer's actual resolved plan.

## Upstream cohort

This edge entails `kiroku-upgrade` 0.12.0.0 → 0.13.0.0 from
mori://shinzui/kiroku. Follow that edge for the exact new Store operations,
StoreError and KirokuEvent constructors, and the migration `0017` cutover.
Resolve Store `^>=0.13.0.1` and migrations `^>=0.7.3.0`; where used, metrics
is `^>=0.4.0.1` and the Shibuya adapter is `^>=0.7.0.1`. The Store patch
preserves asynchronous cancellation through observability and recovery.

Keiro process managers classify `CompactionConcurrentMutation` as transient and
retry the affected command. Custom retry policies must follow the upstream
rollback/fresh-preview guidance when they compose compaction directly. Adopting
destructive compaction is optional; the upgrade does not authorize compaction.

## Composed migrations and fixtures

The framework plan grows from 48 to 49 entries: seventeen Kiroku migrations and
32 Keiro migrations. A database current through the previous release has one
pending Kiroku migration, `0017`. Use the consumer's existing composed runner
(`keiro-migrate` for the standard framework plan); preserve separately composed
PGMQ migrations. Update count, pending-ID, and schema-comment fixtures only where
they describe the full current plan. The Kiroku schema comment becomes
`Managed by pg-migrate component kiroku through 0017`.

Classify persistent databases read-only and report the required operator apply;
rehearse on a disposable restored clone. Existing migration payloads and recorded
checksums do not change, so no ledger fixup is required. Do not drop persistent
databases, rewrite historical migrations/checksums, fabricate ledger entries, or
grant destructive compaction privileges as part of this upgrade.

## Keiro source and generated code

Keiro exports and HTTP routes retain their existing contracts. The HTTP server
now closes accepted sockets even if shutdown prevents their connection workers
from starting; shutdown tests should expect those idle connections to close.
DSL source and language semantics are unchanged. Preserve Language 5 stable and
Language 6 candidate policy; this release does not require generated service
regeneration beyond the consumer's established provenance/version workflow.
Do not overwrite application holes or enable candidate features automatically.
Do not add `allow-newer` to hide an incompatible upstream cohort.
