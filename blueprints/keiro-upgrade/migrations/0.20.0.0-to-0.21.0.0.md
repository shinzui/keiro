# Keiro 0.20.0.0 → 0.21.0.0

## Precondition

The consumer resolves the Keiro package set at 0.21.0.0 and previously used
0.20.0.0. Inspect its dependencies, `.keiro` sources, generated modules, and
direct `Keiro.Dsl.*` imports. If it uses neither the DSL library nor generated
services affected below, report that no source adaptation applies. Keep all
consumed Keiro packages on the shared version.

The upstream cohort and database migration payloads are unchanged. This edge
does not entail an upstream upgrade or require a ledger fixup. Language 5 is
still stable; Language 6 is still a candidate. Preserve the consumer's chosen
language version and feature policy.

## Adapt direct DSL library clients

- `Keiro.Dsl.Grammar.ContractType` now describes shape:
  `CScalar ContractScalarType | CList ContractScalarType`. `CTypeId`,
  `CDeclaredId`, `CText`, and `CInt` now construct `ContractScalarType`.
  Change scalar field construction and matches such as `CText` to
  `CScalar CText`. Handle list shape explicitly; `contractScalar` and
  `contractIsList` are available when the caller needs those views.
- `MappedStructural` and `MappedOpaque` add `msWriteLift` and `moWriteLift`.
  Supply `Nothing` for existing declarations. Checked `StructuralDecl` and
  `OpaqueDecl`, and `StructuralMapping` and `OpaqueMapping` identities, add
  `writeLift`; use `Nothing` when no lift is declared. Update positional
  constructor uses as well as record construction.
- Extend exhaustive matches for `Expr` (`EWriteMapped`, `EWriteInitial`),
  `TypedScalarNode` (`TypedMappedLift`, `TypedMappedInitial`), and
  `LanguageFeature` (`MappedRegisterConstructionSyntax`,
  `ContractListFieldSyntax`). `BindingObligationKind` adds `WriteLiftFunction`
  and `WriteLiftCases`.
- `ExpressionDiagnosticCode` adds `ScalarMappedLiftUnsupported`,
  `ScalarMappedLiftProjectionUnsupported`, `ScalarWriteInitialUnsupported`,
  and `ScalarWriteInitialShadowed`. `MappedDeclError` adds
  `InvalidMappedWriteLift`. `DiagnosticCode` adds `ContractListFieldUsedAsKey`,
  `AggregateExpressionMappedLiftUnsupported`,
  `AggregateExpressionMappedLiftProjectionUnsupported`, `MappedWriteLiftInvalid`,
  `AggregateExpressionWriteInitialUnsupported`,
  `AggregateExpressionWriteInitialShadowed`, `MappedWriteLiftChanged`, and
  `MappedWriteLiftFixturesChanged`. Implement each caller's intended handling;
  do not discard cases merely to silence a compiler warning.

- `MappingIdentity` ledger JSON gains an optional `writeLift` key. Existing absence
  remains valid; do not fabricate historical lift provenance.
- `DiagnosticCode` is Enum/Bounded: the eight inserted constructors shift
  `fromEnum` positions after `ContractTypeIdDomainChanged` and
  `AggGuardRemedyUnavailable`. Do not persist ordinal assumptions as stable codes.
- `Scaffold.behaviorRequirementsFor` is newly exported and partial: it raises an
  error if behavior derivation fails for its expected validated aggregate.
  `ScaffoldRun.pureRefusalsForService` also checks
  `generatedImportResolutionViolations`; handle this pre-write refusal.
- Same-prefix literal-to-declared ID-domain transitions whose old revision
  predates `ContractIdDomainTypeIdV7` now classify as breaking, not advisory.

Schema-1 mapping ledgers remain readable; do not rewrite historical ledgers to
invent lift provenance. Adopting `initial` or `mapped(expression)` register
writes is optional candidate Language 6 work, not an upgrade requirement.

## Regenerate affected services and preserve holes

Use the consumer's established `keiro-dsl scaffold` commands and output paths
with the 0.21.0.0 executable. Inspect the resulting diff.

- Whole-name stems now preserve reserved word boundaries. For example,
  workqueue `job_type` exports `jobTypeJobCodec`, `jobTypePayloadCodec`, and
  `JobTypeOutcome`, replacing the old `jobtype…` names. Projection helpers
  `thingtypeWitness` and `thingtypeGet` become `thingTypeWitness` and
  `thingTypeGet`. Update imports, exports, references, and local aliases to the
  actual regenerated spelling. This renames Haskell declarations, not logical
  DSL names, wire paths, or database objects.
- Create-once read-model hole files are preserved by scaffolding. Manually
  adapt affected query bindings, type aliases, exports, and contract imports
  while retaining their application implementation bodies. Recompile to find
  any remaining references.
- Regeneration rewrites every generated aggregate `BehaviorContract.hs`, even
  without hole-owned initial transitions: it exports `behaviorObligationReport`
  and uses `coverageReportFor`. Additionally, Language 2 and later harnesses
  with hole-owned live initial transitions now use the consumer's history-backed
  `LiveWitness`, expose `behaviorObligationReport`, and report `hole witness
  filled` / `hole witness verified`. Preserve the hole implementations and
  witness histories. Supply a valid witness where one is pending; do not fake
  successful acceptance against empty registers or weaken conformance checks.

The witness fix alone changes neither fold fingerprints nor snapshot identity,
wire shapes, or replay semantics. Existing scalar contract fields retain their
wire representation. List fields and mapped write-lifts need separate consumer
design and compatibility review if deliberately adopted.

## Validate

In the consumer's supported development environment, run its normal build,
generated-service conformance, tests, and replay checks. Direct DSL API clients
must compile with exhaustive-pattern warnings enabled. Verify that renamed
imports compile and that hole witness obligations succeed with real histories.
Review `diff --since` reports before accepting a source change: removals now
produce compatibility and replay-impact reports before the breaking gate exits
nonzero, and same-prefix contract ID admission changes can be public breaking.
Do not bypass that gate as part of this upgrade.

Keiro's own commands proving the shipped changes are:

```sh
nix develop -c z3 --version
nix develop -c cabal test keiro-dsl-test keiro-dsl-conformance-keyword-segments keiro-dsl-conformance-history-dependent-holes --test-show-details=direct
nix develop -c cabal test keiro-migrations-test keiro-ops-test --test-show-details=direct
nix develop -c just verify
```

Run these repository commands when validating a Keiro checkout; in a consumer
use its corresponding targets rather than assuming those suite names exist.

Do not drop databases, edit migration checksums, enable `--allow-schema-drift`
to hide unrelated differences, overwrite consumer-owned holes, or automatically
switch stable services to candidate Language 6. Registry-recorded Keiro runtime
binding views are now accepted by schema verification; unregistered additions
and migration-owned differences still require investigation.
