# Keiro 0.19.0.1 → 0.20.0.0

## Precondition

Apply this edge to a project consuming any Keiro package. Start from a clean
working tree and identify the packages, worker entry points, generated services
and database fixtures it owns. Report an unused surface as not applicable and
continue.

This edge entails the hardening `0.9.0.1 → 0.10.0.0` and inspection
`0.10.0.0 → 0.11.0.0` edges from mori://shinzui/kiroku in that order. Those
edges own Kiroku source and database guidance; establish that they completed or
were reported not applicable before following the steps below. Do not repeat
their work or apply persistent database migrations automatically.

## Align packages

Move every consumed Keiro package to the shared `0.20.0.0` version:
`keiro-core`, `keiro`, `keiro-pgmq`, `keiro-migrations`, `keiro-test-support`,
`keiro-dsl`, and `keiro-ops`. Update direct upstream bounds where present:

- Store `^>=0.11.0.0`, migrations `^>=0.7.1.0`, and adapter `^>=0.6.0.1`
  from mori://shinzui/kiroku.
- Core `^>=0.10.0.1` from mori://shinzui/shibuya/packages/shibuya-core.
- The queue libraries `>=0.6.1.1 && <0.7` from mori://shinzui/pgmq-hs.
  The adapter from
  mori://shinzui/shibuya-pgmq-adapter/packages/shibuya-pgmq-adapter remains
  `^>=0.16.1.0`.

Keep other bounds unchanged unless the consumer has its own reviewed upgrade.
Do not add `allow-newer`, source overrides, or unreviewed pins to force a solve.

## Adapt Keiro failure handling

`ShardWorkerError` gains `ShardReaderStartupFailed Int Text`. Extend exhaustive
matches used for diagnostics or supervision. `ShardCountMismatch` now belongs
to the upstream `SomeSubscriptionStartupFailure` exception family; a direct
typed catch still works. Review broad startup-failure handling for the intended
refusal behavior. Invalid sharded options refuse before starting readers.

The new `runDomainCommandWithCatalogProjectionsGuarded` is opt-in. Existing
catalog command call sites need no rewrite. Do not add synchronous guards or
move asynchronous query models into append transactions as an upgrade step.

## Update composed migration fixtures and operations

Keiro's composed plan grows from 44 to 47 migrations and the Kiroku prefix
grows from 12 to 15. Update inventory/count assertions and prefix slicing in
fixtures to those values. The entailed edges explain migrations 0013–0015,
worker shutdown, legacy target adoption, and the index-build write pause.
Keiro's own historical SQL payloads are unchanged; no Keiro ledger fixup is
required. Do not drop persistent databases or rewrite their migration history.

For a deliberate sharded topology change, stop all workers and relinquish every
Keiro lease first, including expired leases with a recorded owner. Use
`resizeShardCount` or transaction-composable `resizeShardCountTx` to replace
lease rows and rewind public checkpoints together. Same-size resize can
redeliver events. Do not call the upstream-only resize against a Keiro group or
delete lease/checkpoint rows to bypass an owner refusal. Resize is an
application decision, not a mandatory part of this upgrade.

## Regenerate DSL output

For a project owning `.keiro` specifications, regenerate with `keiro-dsl`
0.20.0.0. The expected generated change is the provenance banner from
0.19.0.1 to 0.20.0.0; language and generated APIs are unchanged. Report any
other generated diff before accepting it. Preserve hand-owned fills and commit
the source, ledger and generated output together; do not hand-edit generated
files or weaken warnings to get them building.

## Validate

Run the consumer's normal build, database-backed tests and worker startup/shutdown
checks in its development environment. Keiro itself uses `nix develop -c z3
--version`, `nix develop -c cabal build all --enable-tests --enable-benchmarks`,
`nix develop -c just verify`, and `nix develop -c nix flake check`. Its
`nix develop -c just corpus-regen` and corpus policy prove the generated restamp;
consumer projects should use their corresponding generation check.

The owner deferred the exhaustive guarded-catalog performance matrix. Do not
restart it as an implicit upgrade gate or claim that retained partial/failed
measurements prove a full performance pass. Report exact resolved versions,
source/fixture edits, validation and remaining operator database work.
