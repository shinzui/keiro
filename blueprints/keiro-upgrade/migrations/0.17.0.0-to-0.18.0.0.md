# Keiro 0.17.0.0 → 0.18.0.0

This edge covers required source adaptations for widened public ID-domain and DSL grammar types,
the `ephemeral-pg` floor raised by `keiro-test-support`, and the candidate Language 6 checked value
mappings. The upstream Kiroku, Keiki, and Shibuya cohort is unchanged, so no upstream edge is
entailed. No migration payload changed, so no recorded checksum moves and no ledger fixup is
required to cross this release.

## Precondition

Apply this edge when the project depends on any Keiro package. Each step states which package or
surface makes it applicable. Report an inapplicable step as not applicable and continue; do not
exit nonzero merely because the project does not use that surface. Start from a clean working tree
and identify direct `IdDomainContract` construction, matches on `IdDomainFailure`, matches over
`keiro-dsl`'s exported grammar and resolved ASTs, and test suites that depend on
`keiro-test-support`, before editing.

## Step 1 — Align dependencies

Update every Keiro package the project consumes to the 0.18.0.0 lockstep set. Keep
`kiroku-store >=0.8 && <0.9`, `kiroku-store-migrations ^>=0.4.0.0`, `keiki >=0.9 && <0.10`,
`shibuya-core ^>=0.9.0.0`, `shibuya-pgmq-adapter ^>=0.16.0.0`, and the `pgmq-*` family at
`>=0.6 && <0.7` unchanged. This release moves no upstream cohort member.

If the project depends on `keiro-test-support`, raise its own `ephemeral-pg` bound to
`>=0.3.1 && <0.4`. `pg-migrate-test-support 1.1.0.0` still caps `ephemeral-pg <0.3` while only
using `Config` record updates, which 0.3's new `sweepStaleOnStart` field does not break. If the
project's build plan contains both, add exactly this line to its `cabal.project`:

```
allow-newer:
  pg-migrate-test-support:ephemeral-pg
```

This is the one `allow-newer` this edge authorizes, and only for that pair. Drop it once a Hackage
revision or release widens the cap. Report any other solver conflict rather than adding further
`allow-newer` entries, source-repository overrides, or unreviewed pins.

`keiro-test-support`'s fixture now starts PostgreSQL under `/tmp/ephpg-keiro-<uid>` rather than
`$TMPDIR`. A sandbox or CI runner that forbids writes outside its own temporary directory will fail
at fixture startup; report that rather than working around it.

## Step 2 — Adapt ID-domain consumers

For projects that use `Keiro.Codec.IdDomain`, `IdDomainContract` gains a leading
`idDomainAdmission :: IdAdmission` field. Positional construction must supply it; prefer the
smart constructors `typeIdV7Domain` for the existing behavior and `typeIdV5OrV7Domain` for the new
widened admission. Do not switch an existing domain to `TypeIdV5OrV7` as part of this upgrade —
admission is part of the frozen contract and changing it is a separate, replay-visible decision.

`IdDomainFailure` gains `IdDomainVersionNotAdmitted !Char` and `IdDomainVariantNotRfc4122 !Char`.
Extend exhaustive matches, typically in error rendering. Both carry the offending character from
the canonical suffix, not the whole input; do not log the full identifier if the surrounding code
treats identifiers as sensitive.

`parseKindIdV7Text` and `parseKindIdV7Value` are unchanged and still parse v7 only. The new
`parseKindIdText` and `parseKindIdValue` take an `IdAdmission` explicitly. Existing identity bytes
are unchanged, so no stored value needs rewriting.

## Step 3 — Adapt keiro-dsl library consumers

This step applies only to projects that import the `keiro-dsl` library directly, not to projects
that merely run the `keiro-dsl` executable over a `.keiro` spec.

Extend exhaustive matches over the widened public types. `TypeExpr` gains `TDay` and `TTextSet`;
`MappedShape` gains `ShapeBare !TypeExpr` and `ShapeRefined !RefinedWirePolicy`; `IdDecl` gains an
`admission` field; `LanguageFeature` and `RuntimeCapability` each gain five constructors. The
resolved type, expression, and requirement vocabularies gain matching alternatives (`RBare`,
`RRefined`, `RDay`, `RTextSet`, `ExprDay`, `ExprTextSet`, `ReqDay`, `ReqSet`, `ReqByteString`,
`MappedRefined`, `MCRefinedPolicy`). `RefinedWirePolicy` is newly exported from `Keiro.Dsl.Grammar`
with the single constructor `Base16BytesV1`.

## Step 4 — Re-scaffold DSL services

For projects with a `.keiro` spec, re-scaffold. The provenance banner on every generated file
restamps from `0.17.0.0` to `0.18.0.0`. The recognizer accepts any released stamp, so an
un-regenerated tree keeps compiling; the restamp is the only change for a spec that adopts nothing
new. Commit the source, hand-owned fills, ledger, and generated changes together.

If a generated codec in the project imports `Keiro.Codec.CalendarDay`, `Keiro.Codec.TextSet`, or
`Keiro.Codec.Base16Bytes`, note that `keiro` now re-exports all three. A generated service needs
only its existing direct `keiro` dependency; do not add a direct `keiro-core` dependency for these
modules.

## Step 5 — Adopt checked value mappings (optional)

Candidate Language 6 adds four mapping families. Adopting any of them is a deliberate schema
decision, not part of this upgrade — do not convert existing declarations on the agent's own
initiative.

- Bare containers: a `mapped structural value` declaration may name a container shape directly,
  as `wire Optional Text`, `wire List Text`, or `wire Map Text Text`.
- Calendar days: `wire Day`, lowered to `Keiro.Codec.CalendarDay`.
- Text sets: `wire Set Text`, lowered to `Keiro.Codec.TextSet`.
- Refined base16 bytes: the new `mapped refined` declaration with `wire base16-bytes`, lowered to
  `Keiro.Codec.Base16Bytes`.

A root `Optional` mapped event field accepts an omitted key and decodes it exactly as an explicit
`null`, matching what historical Aeson decoding did for such a field, so retained history that
omits the key keeps replaying. Non-optional mapped roots remain strict and still reject omission.

Each family lowers to a frozen Keiro-owned wire policy rather than a consumer validation callback.
Replacing an existing opaque or consumer-bound declaration with one of these changes the wire
contract and the fold identity of the declaring aggregate: run `keiro-dsl diff` first and treat a
reported replay-affecting finding as a drained-cutover decision, not a routine regeneration.

Candidate Language 6 ID declarations also accept `domain=typeid-v5-or-v7`. Adding it changes direct
and nested fold/replay identity and raises an `IdDomainContractChanged` finding; it is subject to
the same cutover review.

Language 1 through 5 specs are unaffected by every item in this step.

## Validate

Run the consumer's normal build and tests. Confirm the `ephemeral-pg` fixture starts and the
database-backed suites pass, since that bound moved. If any ID-domain error rendering was extended,
exercise it against a value that fails the version and variant checks.

This repository uses `cabal build all`, `just verify`, and `nix flake check` as the reference
gates. Beyond the single `pg-migrate-test-support:ephemeral-pg` entry authorized in Step 1, do not
add `allow-newer`, hand-edit generated files, mutate Keiro tables with ad hoc SQL, change a
declaration's ID admission or wire policy to clear a diff finding, or replay history across an
admission or mapping change without a drained cutover.
