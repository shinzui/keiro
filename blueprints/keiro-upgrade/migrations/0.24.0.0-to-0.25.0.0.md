# Keiro 0.24.0.0 → 0.25.0.0

## Precondition and upstream work

The consumer crosses from Keiro 0.24 to 0.25. Align all eight published packages.
Inspect owned timer, producer, job and tracing configuration plus generated
services and trace assertions. Report unused surfaces as not applicable.
The entailed adapter edges cover Shibuya 0.13 configuration, correlation policy
and processing names; assume that work is already done rather than repeating it.

## Constructors and trace policy

- `TimerRequest` and `TimerRow` gain strict `traceContext :: Maybe TraceContext`.
  Add `Nothing` to legacy constructors and fixtures. Explicit caller context wins;
  traced scheduling APIs capture missing creation context before SQL work.
- `TimerWorkerOptions` gains `tracer :: Maybe Tracer`. Prefer a record update of
  `defaultTimerWorkerOptions`; `Nothing` preserves untraced behavior. The options
  no longer have `Eq`: compare owned policy fields instead of whole options.
  Configure an actual tracer only where the application already owns one.
- `IntegrationProducer` gains `tracePolicy :: ProducerTracePolicy`. Start with
  `PreserveDraftTrace`. Adopt `DeriveTraceAfter cutoff` only with the immutable,
  per-producer/store cutoff and rollout procedure in this release's producer
  guide. Do not recompute a cutoff on restart or change it for replay. Preserve
  existing event identities, explicit draft context and strict retry equality.
- `JobTuning` gains `telemetry`; `mkJobTuning` and `defaultJobTuning` provide
  `ParentAndLink`. Keep that default unless delayed/retried deliveries require
  explicitly chosen `LinkOnly`. The adapter edge explains the trace-shape choice.

## Observability and durable state

Command spans become `command <category>`; the full stream remains available as
`keiro.stream.name`. Mixed outbox batches are named `send`; uniform batches use
`send <destination>`. Per-message IDs and Kafka key attributes belong only on
singleton batch spans. Update owned assertions, queries and alert rules that
assume the previous names, parentage or batch attributes. Durable boundaries use
creation links: do not assert that timer fires or workflow resumes share the
originating trace ID. Report external dashboards requiring operator changes.

Apply new Keiro migration `0033` before upgraded timer/workflow workers start.
It adds nullable timer context and workflow attribution hints; historical rows
remain valid without context. The composed framework plan is 50 migrations
(17 Store plus 33 Keiro). There is no historical checksum or ledger fixup.
Follow the project's database runbook for persistent deployments; do not drop
persistent databases or invent trace context for old rows. Existing journal
identity and snapshot formats remain unchanged. Legacy workflow APIs remain
untraced wrappers; adopt explicit traced APIs only for configured tracing.

## Generated services and validation

Regenerate owned DSL output with the matching 0.25 toolchain and the project's
scaffold command, preserving application holes. Generated timer constructors now
supply `traceContext = Nothing` and worker defaults supply `tracer = Nothing`.
Do not hand-edit generated code, change Language 5 stable / Language 6 candidate
policy, force dependency solves or introduce unrelated migration work.

Use the consumer's development shell and affected build/tests, including its
existing tracing assertions. In this repository the release proving commands are
`nix develop -c just release-gate` and `nix flake check`; the former includes the
existing correctness, retention and benchmark guards. Report resolved versions,
constructor and observability adaptations, migration readiness, regeneration
results and any validation that could not run.
