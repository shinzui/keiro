# 21. Direct fields have independent DSL selector and wire identities

Date: 2026-08-05

Status: Accepted


## Context

A direct aggregate or integration-contract field previously had one spelling for three different
purposes: semantic references in the Keiro DSL, a generated Haskell record selector, and a JSON
object key. That coupling made a generated-name refusal operationally dangerous. Renaming a field
to avoid a Haskell keyword also renamed a live wire key, while keeping a brownfield wire key made
the generated module impossible to compile.

Structural mapped records already distinguish Haskell fields from wire keys. Direct command,
event, and contract fields need the same separation without changing aggregate fold identity or
making shorthand sources noisy.


## Decision

Every direct aggregate command/event field and integration-contract event field resolves three
namespaces:

- The DSL name is the stable semantic identity. Expressions, `fields(Command)` pairing, event
  output authority, diff pairing, and fold canonicalization consume it.
- The generated Haskell selector defaults to the DSL name and may be overridden with
  `haskell <selector>`. Generated records and Haskell accessors consume it.
- The serialized wire key defaults to the DSL name and may be overridden with `as "<key>"`.
  Event and contract codecs plus synthesized JSON goldens consume it.

When both aliases are present, their canonical order is `name haskell selector as "wire": Type`.
The syntax is a language-4 feature in syntax profile 3. Alias-free sources retain their prior
normalized graph and generated bytes.

`fields(Command)` copies the complete resolved field identity into its event shape. Renderers pair
copied fields and hand-owned event-output hooks by DSL name, then choose the selector for Haskell
and the wire key for JSON. They never recompute one namespace from another.

Validation is namespace-specific and occurs during `check`. Explicit selectors must be valid,
non-reserved Haskell occurrences and unique within each generated record scope. Wire keys must be
non-empty and unique within a command, event, or contract event; aggregate event keys cannot equal
the codec envelope key `kind`, and contract keys cannot equal the declared discriminator.
Diagnostics are anchored at the owning field and retain the earlier conflicting location.

Aggregate fold identity deliberately sees only DSL names. Selector changes are presentation-only.
Wire-key changes are codec evolution, not fold evolution: `diff` emits
`EvtFieldWireKeyChanged` for aggregate events and `ContractFieldChanged` for public contracts, and
replay-impact planning selects the affected aggregate event. A command wire-key change is reported
for every `fields(Command)` event that copies it. Selector-only changes emit the existing
`GeneratedHaskellNameChanged` consumer-build advisory and remain replay-neutral.


## Consequences

- A hard DSL word such as `type` can remain the wire key while generated Haskell uses
  `payloadType`.
- Brownfield JSON can keep `region_code` while the DSL uses `region` and Haskell uses
  `serviceRegion`.
- Field selectors and wire keys have distinct collision domains and actionable check-time
  diagnostics.
- Fold fingerprints remain stable when either alias changes; codec diff and replay classification,
  rather than snapshot identity, own wire-key migration evidence.
- Future field-consuming generators must choose a namespace explicitly through the resolved
  field-identity type instead of accepting an unqualified `Text` field name.


## Alternatives considered

**Normalize awkward names automatically.** Rejected because the generated selector would become
an implicit edition-dependent mapping and collisions would be harder to explain. Explicit aliases
make source impact reviewable.

**Use one `as` alias for both Haskell and JSON.** Rejected because it preserves the original
coupling under different syntax and cannot keep a brownfield key while selecting idiomatic
Haskell.

**Include resolved aliases in the fold fingerprint.** Rejected because Haskell presentation is
not runtime behavior and wire compatibility already has direct diff/replay evidence. Changing an
alias must not invalidate snapshots or rewrite frozen aggregate identity.
