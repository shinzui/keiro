# Architecture Decision Record

- [keiro-pgmq job processing emits one process span per delivery on both execution paths](0001-keiro-pgmq-job-processing-telemetry-contract.md) - Both keiro-pgmq job-execution paths emit exactly one process span per delivery under a shared observable contract rather than a shared implementation.
- [Replay-only edges are the sanctioned remedy for guard tightening](0002-replay-only-edges-are-the-sanctioned-remedy-for-guard-tightening.md) - Retired guards keep an inverting edge through keiki's ReplayOnly edge mode instead of the guarded-but-inert command-flag hack.
- [Snapshot compatibility is a three-component discriminator](0003-snapshot-compatibility-is-a-three-component-discriminator.md) - Snapshot compatibility is gated on state codec version, register-layout hash, and control-state/replay-fold hash together.
- [Evolution changes are gated at the earliest sound boundary](0004-evolution-changes-are-gated-at-the-earliest-sound-boundary.md) - Each evolution hazard is checked at the earliest boundary with enough evidence, while later boundaries independently defend runtime assembly.
- [Workflow awaits fall back to the step index on replay misses](0005-workflow-awaits-fall-back-to-the-step-index-on-replay-misses.md) - On an await replay-map miss the workflow interpreter falls back to the generation-scoped step index before arming and suspending.
- [Workflow wake-source rows govern exposure and terminal races](0006-workflow-wake-source-rows-govern-exposure-and-terminal-races.md) - Wake-source rows are the durable authority for exposure and terminal lifecycle while generation-scoped journal entries deliver their results.
- [Workflow sleep timers are generation-owned lifecycle state](0007-workflow-sleep-timers-are-generation-owned-lifecycle-state.md) - The workflow generation that first arms a sleep owns that timer, its fire_at/wake_after hint, and its completion.
- [Workflow failure history is immutable and derived terminal state is revivable](0008-workflow-failure-history-is-immutable-and-derived-terminal-state-is-revivable.md) - Terminal workflow failure history stays append-only immutable while its derived runnable-state projections are explicitly revivable.
- [Keiro owns live schema verification under pg-migrate](0009-keiro-owns-live-schema-verification-under-pg-migrate.md) - Keiro owns live-schema verification as a separate keiro-migrate verify-schema gate, distinct from pg-migrate's ledger-integrity verify.
- [Keiro guards fresh native history over codd ledgers](0010-keiro-guards-fresh-native-history-over-codd-ledgers.md) - A Keiro read-only preflight blocks keiro-migrate up from initializing fresh native history over an existing codd ledger.
- [Kafka consumer fatal errors are surfaced in-band in both poll modes](0011-kafka-consumer-fatal-errors-are-surfaced-in-band-in-both-poll-modes.md) - A raised librdkafka consumer fatal is reported in-band from every poll in both callback poll modes, routine partition conditions never kill a consumer, and consumer close is scope-sequenced rather than left to the garbage collector.
- [Structural consumer mappings use one schema authority and total bindings](0012-structural-consumer-mappings-use-one-schema-authority-and-total-bindings.md) - Keiro-generated structural and nominal representations own private-event wire policy; aggregate, queue, query, and projection consumers resolve through checked schema authorities, consumer bindings are total isomorphisms, snapshots remain separately invalidated, and Keiki projections come from those authorities.
- [Structural coverage is reporting-first and opacity gates are opt-in](0013-structural-coverage-is-reporting-first-and-opacity-gates-are-opt-in.md) - Keiro reports named mapped-type authority boundaries without a global percentage, and rejects opacity only under an explicit operator policy.
- [Service workspaces compose single-owner members under one manifest identity](0014-service-workspaces-compose-single-owner-members-under-one-manifest-identity.md) - A keiro service may span several .keiro files, composed as one graph through a versioned manifest whose service name is the durable identity and whose members each own their declarations outright.
- [Workspace scaffold history is workspace-keyed with attributable adoption](0015-workspace-scaffold-history-is-workspace-keyed-with-attributable-adoption.md) - A whole-workspace scaffold keys its machine ledger and Cabal fragment by the service name, remembers which member produced each module, and imports pre-workspace output only where attribution exists.
- [Source language provenance wraps the semantic Keiro DSL graph](0016-source-language-provenance-wraps-the-semantic-keiro-dsl-graph.md) - A .keiro document selects a registered parser contract, produces located surface syntax, and lowers into a normalized Spec wrapped by source provenance and one effective service semantic contract.
- [Aggregate transitions have explicit generated or Hole behavior ownership](0017-aggregate-transitions-have-explicit-generated-or-hole-behavior-ownership.md) - Each aggregate transition is exclusively generated-owned or explicitly Hole-owned, preserving an honest permanent escape hatch without allowing hand-written code to override checked DSL behavior.
- [Runtime semantics use capability profiles and frozen fold identity](0018-runtime-semantics-use-capability-profiles-and-frozen-fold-identity.md) - Released runtime behavior is selected by explicit monotone capabilities, while replay identity is derived by a total frozen encoder and a fold-only FNV-1a-128 digest.
- [Generated Haskell has an explicit edition and local-extension contract](0019-generated-haskell-has-an-explicit-edition-and-local-extension-contract.md) - The generated manifest owns the compilation baseline and naming edition; generated declarations use checked UpperCamelCase or lowerCamelCase while overwriteable modules declare specialized extensions locally only when needed.
- [Service conformance packages import one runtime-owned facade](0020-service-conformance-packages-import-one-runtime-owned-facade.md) - A configured Keiro service generates at most one local conformance package whose runner imports one generated facade from an explicitly named runtime package while create-once expectations remain application-owned.
- [Direct fields have independent DSL selector and wire identities](0021-direct-fields-have-independent-dsl-selector-and-wire-identities.md) - Direct aggregate and contract fields resolve one stable DSL identity, one generated Haskell selector, and one serialized wire key, with explicit aliases and namespace-specific validation and evolution rules.
- [Generated sidecars use role-bearing names and forward-compatible ledgers](0022-generated-sidecars-use-role-bearing-names-and-forward-compatible-ledgers.md) - Keiro DSL names machine history as explicit-slot ledgers, names pasted build metadata as Cabal fragments, and migrates old names only through an explicit lossless apply step.
- [Workflow discovery is exact and the instance row is the complete wake ledger](0023-workflow-discovery-is-exact-and-the-instance-row-is-the-complete-wake-ledger.md) - A workflow is discovered only when its keiro_workflows row says it has progress to make, so every wake-source lifecycle transition must write that row.
- [Deterministic ids hash UTF-8 seed bytes and are frozen replay identity](0024-deterministic-ids-hash-utf-8-seed-bytes-and-are-frozen-replay-identity.md) - Every Keiro deterministic id hashes the UTF-8 bytes of its seed text, and that derivation may never change again without a versioned migration story.
- [Worker loops isolate failures per pass and per item and report partial progress](0025-worker-loops-isolate-failures-per-pass-and-per-item-and-report-partial-progress.md) - A keiro background worker never lets one transient error end its loop or one bad item end its batch, and its summary counts work finished rather than work attempted.
- [Projection catalogs separate query, target, group, and handler identities](0026-projection-catalogs-separate-query-target-group-and-handler-identities.md) - A validated projection catalog separates query models, physical targets, atomic rebuild groups, and projection handlers while leaving application SQL and schema ownership explicit.
- [Workflow lifecycle markers are append-only and first writer wins](0027-workflow-lifecycle-markers-are-append-only-and-first-writer-wins.md) - Distinct workflow completion, cancellation, failure, and rotation markers arbitrate under one generation lifecycle lock and cancellation never rewrites history.
- [Operator commands wrap supported library APIs and respect schema ownership](0028-operator-commands-wrap-supported-library-apis-and-respect-schema-ownership.md) - Keiro operator commands preserve library invariants, schema ownership, destructive previews, and the standalone-versus-embedded capability boundary.
- [Typed domain decisions are successful additive command outcomes](0029-typed-domain-decisions-are-successful-additive-command-outcomes.md) - Keiro preserves accepted event batches and typed rejection/no-op payloads as successful results while unmatched commands and infrastructure failures remain CommandError.
- [Declarative router selection is bounded, target-normalized, and coordination-versioned](0030-declarative-router-selection-is-bounded-target-normalized-and-coordination-versioned.md) - Candidate Keiro DSL router selection checks a bounded typed post-query contract, normalizes by physical target before dispatch, preserves stable-union command identity, and reports versioned coordination drift.
- [Subscription checkpoint policy is catalog identity and replay safety](0031-subscription-checkpoint-policy-is-catalog-identity-and-replay-safety.md) - Keiro fingerprints every explicit missing-checkpoint policy, rejects current-head seeding after a replayable clear, and composes Kiroku-owned checkpoint resets with rebuild preparation.
- [Catalog fingerprints are canonical and rebuild lifecycle identity is slice-scoped](0032-catalog-fingerprints-are-canonical-and-rebuild-lifecycle-identity-is-slice-scoped.md) - Keiro hashes injective canonical preimages, uses group slices for rebuild lifecycle compatibility, retains whole-catalog provenance, and requires explicit transactional adoption of reviewed slice changes.
