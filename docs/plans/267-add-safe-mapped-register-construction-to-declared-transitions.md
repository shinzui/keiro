# Add safe mapped-register construction to declared transitions


This ExecPlan is a living document. The sections Progress, Surprises & Discoveries,
Decision Log, and Outcomes & Retrospective must be kept up to date as work proceeds.
If durable project context changes, update or create ADRs in docs/adr/ in the same change.


## Purpose / Big Picture


After this plan, an author using candidate Language 6 can keep a transition generated-owned,
declare its guard normally, and still construct a consumer-owned mapped register value. The two
new write-only forms are `initial`, which selects the target mapped declaration's checked initial
symbol, and `mapped(expression)`, which applies one target-declaration-owned, typed, versioned
unary lift over a direct scalar input. Projected fields inside mapped or nominal values remain
unsupported lift inputs, preserving Keiki's guard-only projection rule. A transition can therefore
clear a `MaybeTime`-like register or construct its
`Just markedAt`-like value without handing the guard and every update to an unrestricted
`EdgeBuilder` Hole.

The observable proof is a new compiled `keiro-dsl` conformance service with complementary guarded
siblings. Its generated transducer contains the declared `B.requireGuard` and `B.slot` lines,
uses `K.opaqueLit` for `initial` and `K.TApp1` for the declared lift, passes Keiki's sibling guard
verification, and reaches the same vertex and complete register file through forward execution,
encoded-event replay, and full replay. Mutation checks show that mixed Hole ownership remains
rejected, an unrecoverable command input remains rejected, a changed lift is caught by declared
cases, and a lift-version change moves fold identity and replay impact.

The implementation will fulfill the validated, narrowed form of
[IR-34](../improvement-requests/let-a-guarded-transition-write-a-mapped-register.md). It does not
make every mapped write newly legal: same-typed whole-value copies already work, and arbitrary
construction remains outside the language. It also does not relax
`AggregateTransitionOwnershipConflict` or add a partial `EdgeBuilder` callback.

- Observation (2026-09-21): accepting an arbitrary scalar-typed lift child is unsafe as a plan.

  `termProjectionInfos`; `projectionValidationWarnings` rejects projections in updates with
  `ProjectionOutsideGuard`. Wrapping a projection does not hide it. Reject it in the new lift
  resolver; never change Keiki to admit it. This is a restriction of the new feature, not a
  change to existing Languages 1-5 write diagnostics.

- Observation: Keiki 0.9.1.0 already contains every execution primitive this feature needs.

  function, and `USet` stores the result in one statically named slot. Update operands are not

- Observation: Keiki's recoverability gate is schema-wide, not term-driven. `hiddenInputReasons`
  requires every declared `InCtor` field to be recovered by a top-level `TInpCtorField` in the
  head emitted event (`HirUnionMiss`, `HirHeadUnrecoverable`), regardless of which update terms
  read it; `termReadsInput (TApp1 _ term) = termReadsInput term` only drives the epsilon-edge
  check. Wrapping a command projection in a lift therefore cannot make an unrecoverable command
  replay-safe, but a mutation that drops the field from the head event fails for reasons
  independent of `TApp1`. Keiki also does not descend into derived terms when computing recovered
  slots in outputs (`visitedSlotsOf`), so a lift must never be lowered into an event field.
  Evidence: `hiddenInputReasons`, `visitedSlotsOf`, `termReadsInput`, and `edgeReadsInput` in
  `src/Keiki/Core.hs` at `mori://shinzui/keiki/packages/keiki` 0.9.1.0.

- Observation: `keiro-dsl check` has no command-recoverability diagnostic. Enforcement happens
  when the generated harness runs Keiki's `validateTransducer defaultValidationOptions` and the
  forward/replay register-equality row; both are conformance-time, not check-time.
  Evidence: `keiro-dsl/src/Keiro/Dsl/Harness.hs` (`validateTransducer is empty` row and
  `forwardReplayDecl`); no `HiddenInput`/`Unrecoverable` code exists in
  `keiro-dsl/src/Keiro/Dsl/Validate.hs`.

- Observation: Keiki computes no behavioral identity of a transducer. `Keiki.Shape` hashes only
  type-level state and register-file shape and documents that guards, updates, function bodies,

  identity for a lift and its version is the only detection of a changed lift.
  Evidence: `src/Keiki/Shape.hs` (`stateShapeHash`, `regFileShapeHash`, module Haddock) and the
  absence of any `FoldVersion`/fingerprint symbol in Keiki `src/`.

- Observation: `setSlotN` forces every written slot value to weak head normal form at each step,
  and replay re-runs updates forward from the recovered command. A partial lift therefore throws
  inside `runUpdate` during replay of stored history, not only during the live command.
  Evidence: `setSlotN`, `runUpdate`, `applyEventKernel` in `src/Keiki/Core.hs`.

  Date: 2026-09-21

- Decision: Implement only target mapped `initial` and one declaration-owned unary lift; do not
  generalize all mapped expressions.
  Rationale: same-typed mapped copies already work. These two forms cover the reproduced clear/set
  shape while keeping the permanent language surface small and target-typed.
  Date: 2026-08-21

- Decision: Extend candidate Language 6 in its existing syntax profile 5 while preserving
  runtime-semantics profile 5 (updated 2026-09-21).
  Rationale: published Language 5 is immutable. The new expression is fold-visible only when used,
  so an unchanged aggregate upgraded from Language 5 to 6 need not acquire a global runtime fold
  segment.
  Date: 2026-08-21

- Decision: Use this exact source surface:

  ```text
  mapped opaque MaybeTime {
    haskell package=example module=Example.Domain type=MaybeTime
    codec = "example.MaybeTime.v1"
    version = "1"
    fixtures = "Example.Bindings.maybeTimeCases"
    initial = "Example.Bindings.noTime"
    write-lift from Time {
      function = "Example.Bindings.atTime"
      version = "1"
      fixtures = "Example.Bindings.atTimeCases"
    }
  }

  write dormantSince := initial
  write dormantSince := mapped(cmd.markedAt)
  ```

  Rationale: the outer declaration fixes the target and consumer package. One optional nested
  clause makes the lift unambiguous, keeps all hand-owned provenance together, and leaves the
  write expression free of module/package strings.
  Date: 2026-08-21

- Decision: Restrict the first lift source to one direct aggregate scalar: `Text`, `Int`,
  `Integer`, `Bool`, `Natural`, or `Time`.
  Rationale: those types already have total aggregate expression and generated Haskell lowering.
  The motivating `Time -> MaybeTime` case fits. Containers, `Json`, nominal types, and mapped
  sources would expand type/import/proof policy without a demonstrated need and can receive a
  later language feature.
  Date: 2026-08-21

- Decision: Treat `initial` and `mapped(...)` as complete write right-hand sides, not general
  expression atoms.
  Rationale: construction has a target type only at a write site. A dedicated `pWriteExpr` keeps
  guards, outcomes, rules, and nested arithmetic free of context-dependent meanings. Bare
  `initial` in Languages 1-5 retains its current ordinary-name resolution and diagnostics.
  Date: 2026-08-21

- Decision: Lower `initial` to `K.opaqueLit <qualified-initial>` and lower a lift to
  `K.TApp1 <qualified-function> <typed-source-term>` inside the generated `B.slot` assignment.
  Rationale: both are existing typed Keiki terms. Generated code continues to own the named slot,
  guard, event vector, mode, and target; the application can supply a value/function but cannot
  mutate the edge envelope.
  Date: 2026-08-21

- Decision: A lift function is pure and total by contract, carries a mandatory non-empty version,
  and carries a mandatory `NonEmpty (Text, source, target)` case symbol.
  Rationale: Haskell cannot prove totality or purity in the presence of bottoms and unsafe
  operations, and Keiro does not hash arbitrary source. The type boundary, finite executable
  evidence, explicit version, fold identity, and code review are the honest assurance available.
  Changing the body without changing the version remains a contract violation; tests must not
  claim universal automatic detection.
  Date: 2026-08-21

- Decision: Keep transition `BehaviorOwnership` as `GeneratedOwned`, while recording the
  consumer-owned lift function, version, and cases in mapping provenance and conformance.
  Rationale: the generated machine selects and invokes the declared function in exactly one
  declared write; the function cannot replace the guard or update a second slot. Calling the
  whole edge Hole-owned would discard truthful generated authority, while omitting lift
  provenance would hide hand-owned behavior.
  Date: 2026-08-21

- Decision: Never permit a normal `EdgeBuilder` Hole beside a declared guard or write.
  Rationale: mixed authorities would violate ADR 17 and could silently narrow the guard or modify
  another register outside canonical diff and fold identity.
  Date: 2026-08-21

- Decision: Reject a predicate-valued lift child at check time with the existing
  `ScalarOperatorUnsupported`/`AggregateExpressionOperatorUnsupported` diagnostic, exactly as a
  predicate-valued top-level write is rejected today.
  Rationale: `renderKeikiTerm` lowers predicates with `error`; the only sound boundary for this
  input is the resolver (ADR 4). A `Bool`-sourced lift must not be able to reach the scaffolder
  with `mapped(reg.a == reg.b)`.
  Date: 2026-08-22

- Decision: Under Language 6, a bare `initial` as the complete write right-hand side always means
  the target's declared initial. If the aggregate declares a register named `initial`, or the
  transition's command declares a field named `initial`, the checker raises a new located
  diagnostic (equivalent to `AggregateExpressionWriteInitialShadowed`) that names
  `reg.initial`/`cmd.initial` as the disambiguation. `pWriteExpr` matches `initial` only when it
  is the entire right-hand side; `initial.field`, `initial + 1`, and any qualified spelling fall
  through to `pExpr`. Languages 1 through 5 are untouched.
  Rationale: `initial` is not reserved, so silently changing the meaning of an existing
  Language-5 program on upgrade would be a semantic regression with identical canonical bytes.
  A diagnostic is the only option that keeps Language 5 frozen, keeps Language 6 unambiguous, and
  never reinterprets a program.
  Date: 2026-08-22

- Decision: Add `{-# OPTIONS_GHC -Werror=incomplete-patterns #-}` to `Keiro.Dsl.Scaffold` and
  `Keiro.Dsl.FoldFingerprint` before adding the new constructors, replace every `_` fallback that
  would mishandle `TypedMappedInitial`/`TypedMappedLift` (or the raw `EWriteInitial`/
  `EWriteMapped`) with explicit cases, and add a dedicated write-side value-reference collector
  for the initial and lift symbols alongside the guard-only `typedExpressionImportTypes`.
  Rationale: `src/` builds with non-fatal `-Wall`, so "all walkers must become exhaustive" is
  otherwise unenforced and a missed walker compiles green. Write operand types are deliberately
  not imported, so the lift symbol needs its own collection path rather than a widened type
  collector, which would produce an unused import that is fatal under the generated-output gate.
  Date: 2026-08-22

- Decision: Decode the optional mapping-ledger lift field with `.:?`, keep the per-row
  `schema` at 1 and the record header at v1, and add a test that decodes a ledger written before
  the field existed.
  Rationale: the current decoder uses strict `.:` for every field, and a single failing row drops
  the entire scaffold record. A naive copy of the existing style would silently erase drift
  history for every consumer on the first post-upgrade scaffold.
  Date: 2026-08-22

- Decision: Record used-lift provenance as one additional field of the existing
  transition segment, appended only when the transition uses a lift. Encode the new field as
  compact JSON tuples in write order, with strings escaped, rather than concatenating arbitrary
  version strings with colons (updated 2026-09-21).
  Rationale: only the new payload needs unambiguous framing; a positional field present
  but empty on lift-free transitions would move every pinned digest, which this plan classifies as
  a design stop. Conditional presence also yields "only aggregates whose transition uses the lift"
  in `ReplayImpact`, which recomputes fold surfaces rather than classifying diff codes.
  Date: 2026-08-22

- Decision: A lift is lowered only into a `B.slot` update and never into an event field or
  output hook; the conformance service asserts that no generated event output term contains
  `K.TApp1`.
  Rationale: Keiki does not descend into derived terms when computing recovered slots in outputs,
  so a derived event term cannot establish recovery of its child input or register. Other
  top-level event fields can still make such an event recoverable; do not claim every derived
  output is invalid. This feature stays write-only. Updates are re-run forward from the recovered
  command and remain subject to the projection restriction and consumer totality contract.
  Date: 2026-08-22

- Decision: Consumer-owned nominal register targets receive a dedicated diagnostic from the
  `initial` write form in this plan rather than silent support.
  Rationale: `InitialNominal` is lowered identically and could be admitted later, but admitting it
  here widens the proof surface beyond the reproduced mapped case. Naming it explicitly avoids an
  accidental extension through an unlisted branch.
  Date: 2026-08-22


## Outcomes & Retrospective


The 2026-09-21 refresh establishes feasibility for direct scalar lift inputs using released
Keiki, corrects the candidate-language baseline, and narrows the argument grammar to preserve
Keiki's projection restrictions. The original plan had no provenance block; earlier authorship
and review history are unknown. This refresh does not implement IR-34 or establish its final
conformance acceptance. The generated DSL service, encoded replay, snapshot admission, drift,

## Context and Orientation


The owning package is `mori://shinzui/keiro/packages/keiro-dsl`, whose Cabal file is
`keiro-dsl/keiro-dsl.cabal`. It owns `.keiro` parsing, semantic checking, scaffold generation,
fold fingerprints, semantic diff, replay impact, and compiled conformance. No public runtime API
change belongs in `keiro-core` or `keiro`, and no dependency release is required. Keiki remains
the execution engine through the already-admitted `keiki >=0.9 && <0.10` bound.

A mapped type is a consumer-owned Haskell type described by a `.keiro` declaration. The raw AST
lives in `keiro-dsl/src/Keiro/Dsl/Grammar.hs`; mapped declarations are parsed in
`keiro-dsl/src/Keiro/Dsl/Parser/Mapped.hs`, rendered in
`keiro-dsl/src/Keiro/Dsl/PrettyPrint.hs`, and converted to a complete checked graph in

## Idempotence and Recovery


Parser, checker, pretty-printer, fingerprint, and test commands are read-only or deterministic and
can be rerun after any edit. Scaffolding is also repeatable: generated-owned files may be
regenerated, but consumer-owned bindings, lift implementations, case tables, and witnesses are
create-once obligations and must not be overwritten. Verify this explicitly with the second
scaffold invocation in Concrete Steps before accepting the feature.

The mutation driver must copy each file it changes into a directory created with `mktemp -d`,
install a trap before its first mutation, and restore the originals on success, failure, or
interrupt. It must finish by rerunning the green conformance test. If interrupted before the
trap is installed, inspect `git status --short` and restore only files named by the driver from
its temporary copies; never reset the worktree because unrelated user changes may be present.
