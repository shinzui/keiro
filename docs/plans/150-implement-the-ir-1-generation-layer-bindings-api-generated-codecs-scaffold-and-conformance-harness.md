# Implement the IR-1 generation layer: bindings API, generated codecs, scaffold, and conformance harness

This ExecPlan is a living document. The sections Progress, Surprises & Discoveries,
Decision Log, and Outcomes & Retrospective must be kept up to date as work proceeds.
If durable project context changes, update or create ADRs in docs/adr/ in the same change.


## Purpose / Big Picture

Today `keiro-dsl` can scaffold aggregate fields built only from text, integers, booleans,
declared IDs, declared enums, and the generated vertex type. A consumer with an existing
Haskell domain model — nested records, tagged unions, optional values, opaque JSON leaves —
must either flatten those values into lossy `Text` surrogates or keep them out of the DSL
entirely. The improvement request
`docs/improvement-requests/support-structural-consumer-owned-types-in-keiro-dsl.md` (IR-1)
defines the fix: **structural mapped types**, where a Keiro-generated codec is the single
wire-schema authority and a typed binding connects it to the consumer's existing type, and
**opaque external-codec types**, where Keiro uses the consumer's `ToJSON`/`FromJSON` but
honestly declines to make nested compatibility claims.

The companion plan
`docs/plans/149-implement-the-ir-1-spec-layer-resolved-type-graph-structural-and-opaque-declarations-check-and-diff.md`
delivers everything that operates on `.keiro` text alone: the grammar constructors for
`mapped structural` and `mapped opaque` declarations, the resolved type-expression graph, its
total folds/algebras, `check` rejections, and recursive `diff` classification. **This plan
delivers everything that turns a checked spec into running code**: the published
total `StructuralBinding` runtime API, generated nested encoders and decoders that own the
declared private-event wire schema, a schema-derived Keiki 0.4 field-projection facade for
hand-written Holes, scaffold integration (import discipline, manifests naming consumer packages,
mapping-drift detection in scaffold records), generation-time enforcement of Keiki's
whole-value and constraint rules, the generated conformance harness (binding round trips,
codec goldens, branch coverage, forward-versus-replay equality over mapped registers), and the
IR-1 acceptance conformance package proving all of it end to end on a real compiled aggregate.

After this plan, a developer can write a `.keiro` spec that declares
`mapped structural record ArtifactInfo` with an explicit wire object, run
`cabal run keiro-dsl -- scaffold spec.keiro --out src`, get a generated ring whose codec
emits and parses exactly the declared wire keys while constructing the consumer's own
`ArtifactInfo` type through a hand-owned binding, fill one Holes transducer, and run a generated
harness that fails if the binding, codec, fixture coverage, or replay inversion is wrong.
The observable acceptance is the new conformance suite:
`cabal test keiro-dsl-conformance-structural` passes, its mutation scripts go red when a
nested field or union arm is skipped, and pinned JSON goldens assert that the exercised generated bytes match
the declared contract (research note Experiment A, described in full below).

## Surprises & Discoveries

Document unexpected behaviors, bugs, optimizations, or insights discovered during
implementation. Provide concise evidence.

- Keiki 0.4.0.0 implements typed field projections, but only as guards over direct register or
  matched-input bases with one-way symbolic agreement. Keiro must generate witness provenance;
  the DSL cannot claim nested syntax while guard/write text remains Hole comments.
- `bindingFromShape :: shape -> Either Text a` hid semantic rejection, and current snapshots use
  consumer JSON rather than the generated event codec. ADR 0012 now requires a total two-law
  binding and fingerprint-driven cache invalidation.
- `Keiro.Codec` reaches generated consumers through `keiro`'s explicit Cabal re-export. The new
  module must be added to the same re-export list; dependency transitivity is insufficient.
- The Keiki 0.4 migration also requires `keiki-codec-json` 0.4: the 0.3.1 codec package pins
  `keiki ^>=0.3`, so changing only the direct Keiki bounds cannot solve. Hackage and upstream
  tag `v0.4.0.0` publish both compatible packages.
- Keiro's stream-boundary renderer exhaustively matched Keiki validation warnings. Keiki 0.4
  therefore exposed one deliberate migration site: `ProjectionResultUnsupported`,
  `ProjectionOrderingUnsupported`, and `ProjectionOutsideGuard` now receive explicit,
  provenance-preserving text instead of being hidden by a wildcard.


## Decision Log

- Decision: Place the binding runtime API in `keiro-core` as `Keiro.Codec.Structural`,
  beside `keiro-core/src/Keiro/Codec.hs`, and expose it to generated code the same way
  `Keiro.Codec` is exposed today: add it to `keiro-core`'s `exposed-modules` and add
  `keiro-core:Keiro.Codec.Structural` to `keiro`'s `reexported-modules`. Generated manifests
  continue to list `keiro`, not a second direct runtime dependency.
  Rationale: The API is a runtime contract used by consumer binding modules and generated
  codecs alike; it must live below both, in the package that already owns `Codec`,
  `mkCodec`, and `decodeRaw`. It is a published integration point for plans 151 and 152,
  so it needs one canonical home with a stability note.
  Date: 2026-07-28

- Decision: Stratify the generated ring rather than forbidding all binding-to-generated
  imports. Generate one context-level leaf module per declaration under
  `Generated.<Context>.Structural.Shape.<MappedName>` (for example a module containing only
  `ArtifactInfoShape`). Per-type modules preserve the declaration's exact constructor names without
  collisions between unrelated enums or unions and give binding modules a stable, narrow import.
  A shape module imports only lower shape modules and, for an opaque leaf, the named consumer
  domain module. Hand-owned binding modules may import this `Structural.Shape.*` stratum and the
  `Keiro.Codec.Structural` API and nothing else generated; every
  other generated module may import binding modules. The preflight dependency-plan
  diagnostic (Milestone 3) enforces exactly this stratification.
  Rationale: IR-1 requires that generated imports "point at modules below the generated
  ring and must not introduce a Haskell module cycle", and research note section 9 shows
  the cycle hazard `Generated.Domain -> App.KeiroBindings -> Generated.Domain`. A binding
  of type `StructuralBinding ArtifactInfo ArtifactInfoShape` must name the shape type from
  somewhere; hand-writing shape records would duplicate wire-adjacent structure the
  generator already knows (violating guarantee G6's single-graph rule). A generated leaf
  stratum keeps the shape record machine-owned and acyclic by construction:
  `Generated.Codec -> App.Bindings -> Generated.Structural.Shape.ArtifactInfo -> App.Domain` is a
  straight chain. It also avoids requiring constructor-prefix mangling that would make plan
  151's exact-name generic binding either impossible or heuristic.
  IR-1 itself sanctions this: "a private generated wire representation or type-level shape
  used only by a codec adapter is not a second business model."
  Date: 2026-07-28

- Decision: Correctness first, fusion later. Milestone 2 generates codecs through the shape
  record (`consumer -> shape -> Aeson.Value/Encoding`), and Milestone 5 adds representative
  benchmarks (small record, nested-union, large-list fixtures) that establish a budget.
  Direct-`Encoding` fusion that skips the intermediate shape allocation is performed only
  if the benchmarks show material overhead, and only as an internal change that leaves the
  `StructuralBinding` API and the pinned goldens byte-identical. The hard rule from
  research note section 10 is carried verbatim: **never optimize by restoring dual
  authority** — no fallback to consumer `ToJSON`/`FromJSON` instances in structural mode,
  ever, regardless of measured speedups.
  Rationale: Research note section 10 states the cost is "potential, not yet evidence of a
  material regression", and guarantee G1 outranks throughput.
  Date: 2026-07-28

- Decision: Extend the plan-147 forward-versus-replay harness assertion rather than invent
  a parallel one. If `docs/plans/147-generate-forward-versus-replay-equality-assertions-in-the-dsl-harness.md`
  (a soft dependency) has landed, Milestone 4 extends its assertion so the register
  comparison covers mapped registers using the mapped type's `Eq` instance. If 147 has not
  landed when Milestone 4 begins, this plan implements the assertion for aggregates with
  mapped values following 147's stated design (forward stepping through the emitted event
  chain, then structured replay, comparing the final vertex and every register value),
  using 147's stated conventions (`forwardReplay<Command>` helper naming and the
  `"forward/replay equality: <Command> from <Vertex> -- <check>"` labels) so the two
  implementations converge.
  Rationale: The MasterPlan's Integration Points section assigns the assertion's shape to
  EP-4/147 and its mapped-register extension to this plan; the soft dependency must not
  block the IR-1 conformance contract, which requires the assertion unconditionally.
  Date: 2026-07-28

- Decision: Fixture cases are deterministic labeled enumerations, not `Arbitrary`.
  The single declared fixture binding type is a non-empty list of named consumer values
  (`FixtureCases`), and the harness checks the labels' declared-branch coverage against
  the resolved shape (every union arm and every nullable value in both `Just` and `Nothing`
  form). Missing-key versus present-key behavior is generated directly as a wire-policy case,
  because key absence is not a distinct domain/shape value. Insufficient coverage is a harness
  failure, not a warning.
  Rationale: Research note sections 2 and 6: "the generator remains explicit; Keiro does
  not invent semantically invalid values from `Arbitrary` or `Default`", and "a harness
  should fail when declared branches lack examples instead of accepting one round trip as
  proof of the whole shape." Determinism also keeps pinned goldens stable.
  Date: 2026-07-28

- Decision: Adopt released Keiki 0.4.0.0 as a coordinated breaking dependency migration and
  generate one narrow `StructuralProjections` facade per context. For each eligible field it
  contains a nominal tag, `FieldProjection` instance, and `FieldWitness`, all derived from the
  resolved graph and total binding. Holes use Keiki's `regProj`/`inpProj` directly.
  Rationale: Keiki IR-1 is implemented. Its actual public contract is guards-only, direct
  register or matched-input bases, curated symbolic results, one-way agreement, and a warning
  when composition crosses a non-structural boundary. Generating witness provenance is Keiro's
  responsibility; adding `.keiro` path syntax would be unsound while guard text is only a Hole
  comment.
  Date: 2026-07-28

- Decision: A `StructuralBinding` is a total isomorphism with two separately named law helpers;
  decoding can fail only while parsing JSON into the generated shape. The generator also checks
  `canonicalTypeName (Proxy @a)` against the declared `canonical-type` and never emits an orphan
  instance.
  Rationale: A partial inverse hides consumer invariants from `check` and `diff`; a domain-only
  round trip misses unreachable or incorrectly reconstructed shape values; an unchecked nominal
  name can silently attach the wrong consumer type.
  Date: 2026-07-28

- Decision: Structural codec authority covers private event payloads, not the current snapshot
  cache codec. The mapped wire fingerprint, binding provenance, register initial-value provenance,
  and projection schema are folded
  into snapshot invalidation; mapped registers may still require consumer JSON instances solely
  for cache storage.
  Rationale: `defaultStateCodec` serializes `RegFile` through consumer `ToJSON`/`FromJSON`.
  Claiming generated snapshot execution would misdescribe current code; conservative rebuild is
  the sound integration with ADR 0003.
  Date: 2026-07-28

- Decision: The new conformance package is a `test-suite` stanza
  (`keiro-dsl-conformance-structural`) in `keiro-dsl/keiro-dsl.cabal` with sources under
  `keiro-dsl/test/conformance-structural/`, following the existing 20+ conformance-suite
  convention (exitcode-stdio `Main.hs` driver over `harnessAssertions`), not a separate
  cabal package.
  Rationale: Every existing conformance surface (`test/conformance`, `test/conformance-v2`,
  …) uses this shape, the committed-tree pinning tests in `keiro-dsl/test/Main.hs`
  (`assertMatchesCommitted`) assume it, and the mutation scripts (`test/mutation-test.sh`
  and siblings) key off `cabal test <suite>`.
  Date: 2026-07-28

## Context and Orientation

This repository is the Keiro event-sourcing stack. The packages relevant here (all listed in
`cabal.project` at the repository root) are `keiro-core` (codec and event-stream runtime),
`keiro` (runtime services; generated code's `build-depends` names this package), `keiki`
(external dependency: the symbolic transducer language whose `validateTransducer` checks
decide/evolve soundness; current upstream release `0.4.0.0`, while this repository's pre-plan
bound remains on the 0.3 line), and `keiro-dsl` (the spec language and
toolchain this plan extends; baseline release `0.3.0.0`; the working tree contains
post-0.3.0.0 unreleased evolution work).

Definitions used throughout. A **transducer** is the hand-owned Keiki state machine that
decides commands and folds events. The **generated ring** is the set of modules `keiro-dsl
scaffold` emits and always overwrites; for an aggregate today that is `Domain.hs`,
`Codec.hs`, `EventStream.hs`, `Projection.hs`, and `Harness.hs` under a prefix computed by
`genPrefixFor` in `keiro-dsl/src/Keiro/Dsl/Scaffold.hs` (for example
`Generated/HospitalCapacity/Reservation/Codec.hs`). The **Holes module** is the one
create-once, hand-owned module (`emitHoles`, kind `HoleStub`) the scaffolder writes only if
absent; it holds the transducer, projection application, and upcaster bodies, and is the only
module allowed to use Keiki symbolic operators (enforced by `firewallBreaches` in
`Scaffold.hs`). **Structured replay** is Keiki's reconstruction of the vertex and every
register purely from the emitted private events. A **mapped type** is a consumer-owned
Haskell type bound into the spec either structurally (Keiro generates the codec) or opaquely
(the consumer's `ToJSON`/`FromJSON` runs, and Keiro claims nothing about the bytes inside).
A **binding** is the typed construction/destruction adapter between the consumer type and
the declared structural shape. **HeadUnrecoverable** is Keiki's failure class for a
multi-event edge whose command cannot be inverted from the first emitted event; IR-1
requires that "a mapped value needed to recover a command must be present as an invertible
field in the first emitted private event of a multi-event edge" and that the generated
structure surface this failure rather than mask it.

Key contract text carried forward verbatim from IR-1's Conformance Harness Contract, because
Milestone 4 implements it clause by clause: the generated harness "obtains real mapped
values from declared fixture bindings rather than inventing values for arbitrary consumer
types" and for each structural mapped type and containing private event must exercise
"structural binding round trips between the consumer value and declared shape; generated

"The aggregate conformance package must run `validateTransducer`, the opaque-guard audit,
codec tests, and forward/replay equality. A mapped value read by a state update but omitted
from the first emitted event must make validation or the replay assertion fail."

## Plan of Work

The work proceeds in five milestones with a deliberate arc: first the published runtime API
(so the contract downstream plans consume is fixed early and independent of 149), then codec
generation with goldens (the heart of guarantee G1), then scaffold integration (imports,
manifests, drift, Keiki constraints), then the harness (the finite conformance machinery), and finally
the conformance package that exercises everything, plus benchmarks and ADR/release work.

### Milestone 1 — the `Keiro.Codec.Structural` binding API

Scope: a new module `keiro-core/src/Keiro/Codec/Structural.hs`, exposed as
`Keiro.Codec.Structural` from `keiro-core.cabal`, plus unit tests in keiro-core's existing
test suite. This milestone has no dependency on plan 149 and starts immediately. At the end,
the published integration point that plans 151 and 152 build against exists, compiles, and
is documented.

The module opens with a Haddock **stability note** stating: this module is a published
integration point for consumer binding modules and for keiro-dsl generated code; its types
and field names are stable within a major version; additions are permitted, renames and
semantic changes require a major version bump and a coordinated keiro-dsl release. The note
also states the authority rule verbatim: the generated codec owns the wire schema; a
consumer `ToJSON`/`FromJSON` instance may delegate to the generated codec
(research note section 1's `encodeViaKeiro` direction), and Keiro never delegates structural
encoding to a consumer instance.

The core type follows ADR 0012's consumer-neutral contract:

```haskell
-- | Total construction/destruction boundary between a consumer-owned type
-- and its declared structural shape. Consumer invariants must be represented
-- by the shape or the declaration must be opaque.
data StructuralBinding a shape = StructuralBinding
    { bindingToShape   :: !(a -> shape)
    , bindingFromShape :: !(shape -> a)
    }
```

Field names are prefixed (`bindingToShape` rather than `toShape`) to keep the record safe
to import unqualified next to generated code; the plan-151 skeleton generator will emit
these names, so they are part of the stable surface. Alongside it:

```haskell
-- | Deterministic, labeled fixture cases. The generated harness checks the
-- cases' coverage against the declared shape (every union arm, nullable
-- values both Just and Nothing) and fails on gaps. Missing-key cases are
-- generated as decoder inputs. Never derived from
-- Arbitrary or Default.
newtype FixtureCases a = FixtureCases
    { fixtureCases :: NonEmpty (Text, a) }

bindingDomainRoundTrip :: Eq a => StructuralBinding a shape -> a -> Bool
bindingShapeRoundTrip :: Eq shape => StructuralBinding a shape -> shape -> Bool

-- | Delegation helpers for consumers who want their instances to execute
-- the generated codec (the sanctioned direction).
encodeViaBinding :: StructuralBinding a shape -> (shape -> Value)         -> a -> Value
decodeViaBinding :: StructuralBinding a shape -> (Value -> Either Text shape) -> Value -> Either Text a
```

`decodeViaBinding` propagates only the shape decoder's error and applies
`bindingFromShape` purely after that succeeds; it introduces no hidden semantic rejection.

A single fixture is the one-element case of `FixtureCases`; the spec's mandatory `fixtures`
clause maps directly to a consumer symbol of type `FixtureCases a`. Initial-value
bindings need no wrapper type: a mapped register's `initial-value` clause names a consumer
symbol of the mapped Haskell type itself; the generated `Domain.hs` splices it into the
initial register file. The harness rejects empty labels or duplicate labels so failures and comparison
observations retain a stable identity. Add unit tests covering both binding laws and the
delegation helpers.

- Mapped values remain whole values for writes and emits. Eligible scalar fields may be read in

  so GHC failures are legible rather than hidden behind one vague "codec" constraint. Every
  structural mapped consumer type supplies `CanonicalTypeName`,
  and the harness checks it
  against the declaration. A mapped register additionally supplies the existing snapshot-shape
  constraints plus `ToJSON`/`FromJSON` because the current snapshot cache serializes the register
  file through consumer instances; compilation fails without them.
  The mapped `wireFingerprint`, binding symbol/version, register initial-value symbol, and
  projection-schema identity are
  incorporated into the generated fold fingerprint so a change invalidates and rebuilds the
  cache. The event codec is not described as the snapshot codec. Haskell compilation is the final check
  — keiro-dsl does not claim to inspect consumer source (IR-1 Validation and Scaffolding

  which mapped types are register types; only those require the `initial-value` clause. If

  read by a state update must be recoverable from the **first** emitted event. Generation

### Milestone 4 — the generated conformance harness

Scope: `keiro-dsl/src/Keiro/Dsl/Harness.hs` learns mapped types. At the end, a scaffolded
aggregate with mapped values gets a `Harness.hs` whose `harnessAssertions` implement the
IR-1 Conformance Harness Contract clause by clause, and whose assertions fail on
insufficient fixture coverage.

Extend `emitHarness` (keeping the `harnessAssertions :: [(String, Bool)]` shape and the
existing label conventions so hand-written `Main.hs` drivers keep working):

- Replace the `error "sample: unsupported type"` fallback for mapped types with the one declared
  non-empty `FixtureCases` binding; the harness iterates every labeled case.
- **Binding laws**: for each structural mapped type and each domain fixture case,
  `bindingDomainRoundTrip <binding> <value>`, plus `bindingShapeRoundTrip` for generated shape
  cases assembled to target every wire-policy/union branch. The assembler fills unaffected
  fields from each declaration's deterministic first fixture and obtains opaque leaf values only
  from that opaque declaration's fixtures; it never invents an opaque/domain value or constructs
  the full branch cross-product. Labels distinguish domain and shape law failures and name the
  canonical type/case.
- **Generated-codec round trips**: encode-then-decode equality per fixture case and per
  containing event, plus **pinned JSON goldens**: the golden machinery
  (`Goldens.hs` embedding, never-overwrite rule) extends to mapped payload fields so the
  literal bytes of the declared wire contract are asserted, not just round-trip closure.
- **Wire-policy cases**: for each structural object, decode assertions for each optional
  field missing (expecting the declared on-missing default), explicit null, and the
  declared unknown-field policy; for each union, one decode/encode assertion per declared
  arm using its wire tag.
- **Canonical identity and projections**: assert the consumer `CanonicalTypeName` equals the
  declared `canonical-type`; assert every generated witness agrees with its concrete getter,
  projection guards validate, and repeated reads share a structured projection key. Output/update
  use must yield `ProjectionOutsideGuard`; computed bases are a compile-fail case because
  `ProjBase` exposes only `PBReg` and `PBInp`; composition across a non-structural boundary is
  separately asserted as `NonStructuralProjectionBoundary`.
- **Branch-coverage obligations**: the emitter computes, from the resolved shape, the
  obligation set (every union arm and every nullable value in both `Just` and `Nothing` form) and emits an
  assertion `"fixture coverage: <CanonicalType>"` that is `False` when the declared fixture
  cases do not witness every obligation — a harness failure, not a warning (research note
  section 6). Missing-key/present-key and explicit-null decoder cases are generated by the
  wire-policy assertion family; they are not falsely attributed to domain fixtures.
- **Outer surfaces**: existing event-tag/schema-version and historical upcaster golden
  assertions extend over events containing mapped fields unchanged (the upcaster rung
  machinery is byte-level and needs no mapped-specific change, but goldens for mapped-
  bearing events must exist — synthesized from fixture case one when not hand-captured).
- **Forward-versus-replay equality over mapped registers**: per the Decision Log, extend
  plan 147's assertion (or land its design here if 147 is unmerged): step the transducer
  forward from the initial state through a scripted command sequence built from fixture
  values, collect the emitted event chain, run structured replay over that chain, and
  compare the final vertex and **every register value** — registers compared one by one via
  indexed lookup (`RegFile` has no `Eq`), mapped registers with the consumer type's `Eq`.
  Keep plan 147's convention: helper declarations named `forwardReplay<Command>`, labels
  `"forward/replay equality: <Command> from <Vertex> -- <check>"`, one `register <name>`
  row per declared register (mapped registers extend the same rows). A mapped
  value read by a state update but omitted from the first emitted event of a multi-event
  edge must make this assertion (or `validateTransducer`) fail; that is the IR-1 negative
  contract this assertion exists to catch.
- **Opaque mode**: harness asserts only boundary behavior — the consumer codec round-trips
  the fixture cases and the declared codec identity/version appears in the record — and
  deliberately generates **no** nested key/tag/default assertions below the boundary.

**Soundness gate — the ten-question Proposal Test** from
`docs/research/14-structural-consumer-type-tradeoffs.md`, answered for this plan:

1. *Authority.* The `.keiro` declaration owns the wire schema; the executed codec is
   generated from it in `<gen>/Codec.hs`. The binding constructs/destructs consumer values
   only. Opaque mode is the explicit, labeled exception with no nested claims.
2. *Replay.* Forward register updates over mapped values are reconstructed from emitted
   private events alone; the generated forward/replay assertion compares every register,
   and first-event invertibility violations fail validation or that assertion.
3. *Visibility.* Eligible scalar projections are explicitly exposed to hand-written Holes using
   Keiki 0.4's validated terms. No `.keiro` nested path is claimed, and writes/emits remain
   whole-value. `validateTransducer` plus exact negative diagnostics gate every conformance driver.
4. *Compatibility direction.* Owned by plan 149's `diff` (usage-aware, per surface); this
   plan contributes the goldens and binding-identity records that make those
   classifications testable, and changes no classification semantics.
5. *Ownership.* Generated code imports consumer private types; public contracts keep
   contract-owned types (no change to contract nodes in this plan); shapes are private
   generated wire representations, not business types.
6. *Completeness.* Every emitter constructs plan 149's total algebra; a new type-expression
   constructor without codec/shape/projection/harness handling is a compile error. Deliberate
   constructor-addition tests verify the named sites fail.
7. *Migration.* Goldens are pinned and never overwritten; upcaster goldens extend over
   mapped-bearing events; byte-level evidence (not constructor spelling) defines the
   contract. Shadow comparison is plan 152's extension of this machinery.
8. *Recovery.* Scaffold refusals fire before any write; generated files are the only
   overwritten files; Holes and bindings are never touched; re-runs are idempotent; a
   failed generation leaves the previous committed ring intact and the old release
   unaffected.
9. *Performance.* Milestone 5 measures it; fusion is the sanctioned remedy; restoring dual
   authority is prohibited in the Decision Log and this section.
10. *Negative proof.* The three mutation scripts plus the branch-coverage failing assertion
    and the opaque pinned-text test provide the required falsification cases; they do not prove
    correctness outside the generated fixture corpus.


## Idempotence and Recovery

Every milestone is additive and safely re-runnable. `keiro-dsl scaffold` overwrites only
`Generated`-kind files, never Holes, bindings, goldens, or anything outside its record; the
never-delete/stale-report rule is preserved, so re-running any Concrete Step is safe. The
scaffold record's new `mapping` rows are ignored by older parsers (unknown-line tolerance),
so mixed-version tooling degrades to the old behavior rather than failing. Golden files are
never overwritten; to regenerate a wrong synthesized golden, delete the specific file and
re-run scaffold. Mutation scripts back up the file they mutate and restore on trap; if a
script is killed hard, restore with `git checkout -- <path>`. If a milestone must be
abandoned midway, `git status` plus the Progress checklist identify the split; nothing in
this plan migrates data or touches a database. ADR edits are recoverable via git; re-running
`okf validate` is side-effect free.
