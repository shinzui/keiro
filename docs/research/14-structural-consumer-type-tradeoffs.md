# Structural Consumer Types: What Keiro Gives Up and How to Recover It Safely

**Date:** 2026-07-28

**Status:** Design exploration, not an accepted architecture decision

**Scope:** The structural and opaque consumer-owned type constraints proposed by
[IR-1](../improvement-requests/support-structural-consumer-owned-types-in-keiro-dsl.md)


## Executive Summary

IR-1 deliberately makes `keiro-dsl` less permissive. A type cannot be declared structurally while
an unrelated consumer `ToJSON` or `FromJSON` instance remains the codec that actually writes and
reads history. A mapped value cannot automatically gain nested field access, map membership,
collection mutation, or quantified guards in Keiki merely because its Haskell type compiles. A
private aggregate type also cannot become a public integration contract by accidental reuse.

These restrictions sacrifice convenience, some expressiveness, and potentially some performance.
They do not sacrifice functional event sourcing or consumer-owned business types. Their purpose is
to ensure that every guarantee Keiro reports corresponds to the code that runs.

The most promising improvements do not relax those boundaries. They reduce the cost of satisfying
them:

1. generate or derive typed bindings while keeping wire keys and tags explicit;
2. let consumer JSON instances delegate to a Keiro-generated codec, never the reverse;
3. add shadow-codec migration tooling that compares old and generated bytes over a golden corpus;
4. make use-site evolution diagnostics explain why one nested change has different replay and
   rollout consequences;
5. add new symbolic field/collection operations only after Keiki can represent and validate them;
6. generate explicit private-to-public mapping scaffolds without collapsing the two contracts;
7. fuse structural adapters and generated encoders after benchmarks identify real overhead.


## The Guarantees We Are Protecting

Any ergonomic improvement should preserve these invariants.

### G1 — The declared wire shape is the executed wire shape

If `keiro-dsl diff` reasons about a field named `content_hash`, the generated encoder and decoder
must actually use `content_hash` with the declared presence, null, default, and type policy.
Testing a few examples against an arbitrary codec is useful evidence, but it is not ownership of
that codec's behavior.

### G2 — Private events mechanically reproduce forward state

An event-changing edge must emit enough information for structured replay to reconstruct the
vertex and every register. A mapped value used by a state update cannot be recovered from an
opaque side computation that is absent from the event.

### G3 — Compatibility is evaluated from the correct direction

Private history asks whether the new binary can read old events. A rolling deployment may also ask
whether an old binary can read newly emitted events. A public contract asks whether independent
consumers can continue decoding. A snapshot asks whether its captured state can be hydrated.
These are different questions and may produce different classifications for the same nested edit.

### G4 — Solver-visible claims correspond to Keiki terms

A Haskell predicate that happens to return `Bool` is not automatically visible to Keiki's
symbolic validation. Nested access or collection logic is solver-visible only when Keiki has a
first-class term, evaluator, validator support, and tests for it. Otherwise it must be rejected or
reported as an explicitly opaque guard.

### G5 — Private and public ownership remain separate

Private events optimize aggregate replay and evolution. Public integration messages optimize
consumer stability and meaning. Similar fields may justify generated assistance, but not one
shared type whose change silently alters both contracts.

### G6 — Generation is deterministic and complete

Parser, validation, diff, replay-impact output, scaffold planning, manifest generation, codecs,
and the conformance harness must traverse the same resolved type graph. Adding a new type
expression cannot silently omit one subsystem.


## Tradeoff Map

| Constraint | What we give up | Guarantee protected | Safe improvement direction |
|---|---|---|---|
| Structural mode uses a Keiro-generated codec | Direct reuse of arbitrary consumer JSON instances | G1, G3 | Derive bindings; make consumer instances delegate to generated codecs; add shadow comparison |
| Opaque mode has no nested diff | Field-level compatibility reports for external codecs | G1, G3 | Version/fingerprint opaque codecs; promote a type to structural only with an owned schema |
| Whole mapped values only in Keiki | Ad hoc nested guards and updates | G2, G4 | Add typed symbolic projections/operators to Keiki before exposing DSL syntax |
| Stable artifacts use separate streams | One-stream atomic catalog updates and simple stream counts | G2, G4 | Idempotent orchestration; verified bounded collections only where invariants require them |
| Explicit fixtures and initial values | Automatic `Default`/arbitrary sample generation | G2, G6 | Typed fixture/generator bindings; uninitialized lifecycle vertices |
| Usage-aware evolution | One simple additive/breaking label | G3 | Better explanation, policy profiles, and rollout planning—not weaker classification |
| Public DTOs remain distinct | Zero-copy type reuse between private and public events | G3, G5 | Generate mapping skeletons or schema projections while retaining separate types |
| Imports must stay below the generated ring | Arbitrary module placement | G6 | Binding leaf modules, preflight cycle diagnostics, generated package snippets |
| No recursive structural mappings initially | Direct modeling of recursive trees/graphs | G1, G6 | Reference-based schemas or explicitly bounded/validated recursion |


## 1. We Give Up Arbitrary Codec Reuse in Structural Mode

### The convenience being lost

Suppose an application already has this type and codec:

```haskell
data DocInfo = DocInfo
  { key :: Text
  , contentHash :: Maybe Text
  }

instance ToJSON DocInfo where
  toJSON DocInfo{..} = object
    [ "key" .= key
    , "contentHash" .= contentHash
    ]
```

The most convenient DSL design would import `DocInfo`, declare a structural field named
`content_hash`, and continue calling the existing instance. That creates two authorities:

```text
DSL claim:       content_hash
executed codec:  contentHash
```

`diff --since` would reason about a wire key the runtime never emits. This is worse than having no
structural check because the tool reports false confidence.

### The accepted constraint

Structural mode uses an explicit typed binding and a Keiro-generated codec:

```haskell
data DocInfoShape = DocInfoShape
  { shapeKey :: Text
  , shapeContentHash :: Maybe Text
  }

docInfoBinding :: StructuralBinding DocInfo DocInfoShape
docInfoBinding = StructuralBinding
  { toShape = \DocInfo{..} -> DocInfoShape key contentHash
  , fromShape = \DocInfoShape{..} -> Right (DocInfo shapeKey shapeContentHash)
  }
```

The generated codec owns the `content_hash` wire key and calls the binding only to construct or
deconstruct the consumer value.

### Improvements that keep the guarantee

**Generate the binding skeleton.** The scaffolder can emit a create-once module with every
construction and destruction case typed but unfinished. Adding a field then creates a compiler
error at the application boundary instead of requiring the author to discover the missing work.

**Derive nominal adapters, not wire policy.** `GHC.Generics`, Template Haskell, or a source plugin
could derive record construction when field correspondence is unambiguous. Wire keys, union tags,
presence, nullability, and defaults must remain explicit in the `.keiro` specification.

**Invert codec ownership.** An application that wants a `ToJSON DocInfo` instance can delegate it
to the generated Keiro codec:

```haskell
instance ToJSON DocInfo where
  toJSON = encodeViaKeiro docInfoCodec
```

Now both entry points execute one codec. Allowing Keiro to delegate to the arbitrary instance would
restore the original unsoundness.

**Add a migration comparison command.** A command such as the following could run old and generated
encoders over a declared corpus before cutover:

```bash
keiro-dsl codec compare service.keiro \
  --type DocInfo \
  --fixtures test/fixtures/doc-info
```

It should report byte equality, semantic JSON equality, decode differences, and missing coverage.
Passing the comparison is migration evidence; the generated codec remains the authority after
cutover.


## 2. Typed Bindings Add Boilerplate and Another Compile Boundary

### The convenience being lost

A mapped record now needs package, module, Haskell type, canonical identity, binding, fixture, wire
metadata, and sometimes an initial value. This is more ceremony than writing `external DocInfo`.
Large domains may contain dozens of types and hundreds of fields.

The boilerplate is not all accidental. Each item answers a distinct question:

- package/module/type: what does generated Haskell import?
- canonical identity: what stable shape does a snapshot or diagnostic name?
- binding: how is the business type constructed and deconstructed?
- fixture: how does generated conformance obtain a real value?
- initial value: what does an initialized register contain before any event?
- wire metadata: what bytes are persisted?

### Improvements that keep the guarantee

**Use completion-oriented scaffolding.** Generate a create-once binding module whose missing
functions are explicit typed holes. Re-scaffolding should report newly required holes without
overwriting completed functions.

**Allow shared fixture generators.** A declaration could name a total generator rather than one
fixed sample:

```text
fixture-generator Mori.Project.KeiroBindings.genDocInfo
```

The harness can then cover optional branches and every union arm. The generator remains explicit;
Keiro does not invent semantically invalid values from `Arbitrary` or `Default`.

**Generate an authoring report.** `keiro-dsl check --explain-bindings` could list every required
symbol, expected Haskell type, owning package, and reason. This reduces search cost without
weakening validation.

**Scope initial values to actual registers.** Commands and event-only payloads do not need initial
values. A mapped register does. The resolved graph should compute this requirement from use sites
rather than demanding meaningless defaults globally.


## 3. Opaque Mode Gives Up Nested Compatibility Knowledge

### The convenience being preserved

Some values are genuinely controlled elsewhere, such as a vendor GeoJSON payload or a signed
token with its own codec release process:

```text
mapped opaque VendorGeometry
  haskell package vendor-geometry
  haskell type Vendor.Geometry
  codec "vendor.geometry.json" version "3"
```

Keiro can import, store, emit, and round-trip the value, but it cannot truthfully say whether a
field inside version 3 was renamed or removed.

### What is sacrificed

`diff --since` reports only changes to the opaque boundary, codec identity, or version. A breaking
nested edit that keeps the same declared version is invisible to Keiro.

### Improvements that keep the guarantee

**Require codec identity and version/fingerprint.** This turns silent external drift into an
explicit spec diff. It does not prove compatibility, but it prevents Keiro from claiming more than
it knows.

**Attach an external schema as a new owned mode.** If a producer supplies authoritative JSON
Schema, Dhall, or another structural schema, Keiro could add a schema-bound mode. That mode becomes
structural only if generated codecs or validated adapters execute that schema. Merely attaching a
descriptive schema to an arbitrary codec is still opaque.

**Support conformance evidence without upgrading the claim.** Fixture corpora, external test
reports, or codec hashes can be included in release evidence. They may justify operator trust but
must not silently change an opaque diagnostic into a structural guarantee.


## 4. Whole-Value Semantics Give Up Ad Hoc Nested Keiki Logic

### The convenience being lost

It is tempting to write guards such as:

```text
when command.doc.audience == Internal
when member command.package.dependencies "aeson"
update register.doc.contentHash = command.doc.contentHash
```

If the DSL lowers these to arbitrary Haskell functions, the code runs but Keiki's validator cannot
reason about the predicate or update. The specification would again overstate its guarantees.

### The accepted constraint

Mapped values may be copied wholesale where Keiki's required constraints exist:

```text
event ProjectDocUpdated { doc = command.doc }
update register.doc = command.doc
```

Domain decisions should usually carry solver-visible scalar fields separately:

```text
command ObserveDoc {
  key         : Text
  contentHash : Text
  doc         : DocInfo
}

when register.contentHash != command.contentHash
```

The transducer decides from the scalar `contentHash`; the complete `DocInfo` is still emitted for
replay and projection.

### Improvements that keep the guarantee

**Add typed symbolic projections.** Keiki could gain a first-class projection term whose semantics
are represented in its AST and evaluator:

```haskell
projectField
  :: FieldWitness "contentHash" DocInfo Text
  -> Term DocInfo
  -> Term Text
```

The witness must be generated from the same structural binding graph, and validation must test
evaluation, equality constraints, replay inversion, and diagnostic rendering. Only then should
the DSL expose `command.doc.contentHash`.

**Promote frequently guarded values to explicit scalars.** This is the low-risk path and often a
better domain model: identity, revision, lifecycle, and content hash are decision state; the full
payload is event/projection data.

**Do not hide an escape hatch.** An opaque Haskell predicate can remain possible only if it is
named as opaque, produces an audit warning, and cannot satisfy a deployment gate that requires
fully checked guards.


## 5. Separate Artifact Streams Give Up Monolithic Atomicity

### The convenience being lost

A single Project stream containing a map of every document, package, OKF concept, and extension
entity makes one registration appear atomic. It also permits one command to compute an arbitrary
snapshot diff.

That shape conflicts with Keiki's static event chains and solver visibility. Map membership,
quantification, and dynamic-length diffs become opaque functions. Large unrelated updates also
contend on one stream version.

### The accepted constraint

Stable entities use independently keyed streams. A reconciler dispatches observations and
removals; each hydrated transducer decides Added, Updated, no-op, or Removed from scalar state.

What is sacrificed is all-or-nothing visibility of an arbitrarily large catalog update. Recovery
becomes convergence across multiple idempotent streams rather than one append.

### Improvements that keep the guarantee

**Make orchestration state first class.** Persist reconciliation generation, desired inventory
hash, per-target progress, and activation state. Readers that require a coherent generation can
filter by the activated generation rather than assuming every append happened together.

**Use database transactions for bounded invariants.** Kiroku can atomically append a known bounded
set when a real invariant requires it. This should not be generalized into a dynamic opaque diff.

**Research verified bounded collections.** Keiki could support a fixed-size vector or finite map
only if membership/update operators have explicit symbolic semantics and validation remains
tractable. The proposal must define size limits, SMT encoding, replay inversion, and complexity
failure behavior before the DSL exposes it.


## 6. Explicit Initial Values and Fixtures Give Up Convenient Defaults

### The convenience being lost

Generating `mempty`, `def`, or `error "uninitialized"` is easy. It is often semantically wrong:

```haskell
ProjectId ""        -- type-correct, domain-invalid
error "unset doc"   -- compiles, fails during hydration or validation
```

Arbitrary generic fixtures may also miss the union arm or null/default case that breaks the codec.

### Improvements that keep the guarantee

**Prefer lifecycle vertices over fake values.** An `Absent` vertex can make a payload register
unavailable until an import/add event initializes it. If Keiki's typed register model cannot
express that safely, improving uninitialized-register tracking is better than inventing defaults.

**Support explicit constructor/generator bindings.** Let the application provide values known to
satisfy its invariants. Generate coverage obligations for every arm and presence/null branch.

**Report insufficient fixture coverage.** A harness should fail when declared branches lack
examples instead of accepting one round trip as proof of the whole shape.


## 7. Usage-Aware Evolution Gives Up a Simple Universal Label

### The convenience being lost

The rule “adding a union arm is additive” is easy to explain and automate. It is also incomplete.
Consider adding `Archived` to a status union:

- a new binary replaying old private events can still decode them;
- an old binary may fail if the new producer starts emitting `Archived` during a rolling deploy;
- a closed public consumer may reject the new arm indefinitely;
- a snapshot shape may require a version bump even if event replay is unaffected.

One global label either blocks safe changes or permits unsafe ones.

### Improvements that keep the guarantee

**Produce a compatibility vector.** Report dimensions instead of one word:

```text
private-history-read: additive
old-binary-read-new-events: breaking
snapshot-hydration: unaffected
public-consumer: breaking
rollout: producer-last
```

**Add policy profiles.** A service can declare whether it permits producer-last rollouts, closed
consumer unions, snapshot rebuilds, or mandatory upcasters. Profiles select obligations; they do
not rewrite facts about the change.

**Improve explanations and remediation.** `diff --explain` should name the nested path, containing
roots, compatibility direction, and available remedies: version bump, upcaster, deployment order,
or contract revision.


## 8. Separate Public DTOs Give Up Direct Type Reuse

### The convenience being lost

This is concise but couples private replay to external consumers:

```haskell
publish :: ProjectDocUpdated -> IntegrationEvent ProjectDocUpdated
```

A field needed only to reconstruct a private register now becomes public forever. Conversely, a
public naming change may force private event evolution.

### The accepted constraint

Use a contract-owned DTO and explicit mapping:

```haskell
data DocumentChangedV1 = DocumentChangedV1
  { projectRef :: Text
  , documentRef :: Text
  , action :: DocumentAction
  }

toDocumentChangedV1
  :: RecordedEvent ProjectDocUpdated
  -> DocumentChangedV1
```

### Improvements that keep the guarantee

**Generate mapping skeletons.** Keiro can compare shapes and scaffold create-once mapping holes,
but the mapping remains explicit and compiler-checked.

**Allow schema projection declarations.** A contract may declare that selected private fields
populate selected public fields. The generated output is still a distinct DTO with an independent
version and compatibility report.

**Optimize representation only after ownership is clear.** Internal zero-copy implementation is
acceptable if it cannot make one type declaration the accidental source of both contracts.


## 9. Import Discipline Gives Up Arbitrary Module Placement

### The convenience being lost

Generated modules import the consumer type and binding. If the binding imports the generated
event or codec module, Haskell forms a cycle:

```text
Generated.Domain -> Application.KeiroBindings -> Generated.Domain
```

IR-1 therefore requires binding modules below the generated ring. That can force refactoring of
types currently defined beside application handlers.

### Improvements that keep the guarantee

**Generate a dependency plan before writing.** Scaffold diagnostics should show the proposed
module graph, package dependencies, aliases, and exact cycle path.

**Recommend leaf binding modules.** Keep consumer types and bindings in small modules that import
only domain primitives and the Keiro binding API. Generated modules may safely import those leaves.

**Split packages only when the graph proves it necessary.** A small domain-contract package can
break cycles for large applications, but Keiro should not prescribe a package explosion when a
module-level leaf is sufficient.


## 10. Structural Adapters May Add Runtime Cost

### The possible cost

A naive generated encoder may allocate an intermediate shape before producing JSON:

```text
DocInfo -> DocInfoShape -> Aeson.Value -> bytes
```

An existing hand-written codec might encode directly. The binding may also traverse a large value
twice for validation and encoding.

This is a potential cost, not yet evidence of a material regression. Event-store writes often pay
database and JSON costs that dominate one record conversion, but hot queue or snapshot paths may
differ.

### Improvements that keep the guarantee

**Generate direct encoders and decoders.** The typed binding can expose field construction and
destruction in a form the generator fuses into Aeson `Encoding` without allocating a public
intermediate record.

**Benchmark representative shapes.** Add small, medium, nested-union, large-list, and map fixtures.
Compare allocation and throughput between the historical codec and generated codec. Establish a
budget before optimizing.

**Separate debug validation from production encoding.** Development builds can assert binding
round trips aggressively. Production can execute the same generated codec without redundant
checks once conformance has passed.

**Never optimize by restoring dual authority.** Falling back to an arbitrary faster codec while
continuing to classify the generated structural schema is not a valid optimization.


## 11. Rejecting Recursive Structural Types Limits Some Domains

### The convenience being lost

Trees and recursive expressions are natural Haskell values:

```haskell
data Expr = Literal Int | Add Expr Expr
```

Unbounded structural recursion complicates graph resolution, fixture completeness, diff paths,
codec termination reasoning, and generated harness size. IR-1 initially rejects it.

### Improvements that keep the guarantee

**Prefer identity references for event-sourced graphs.** Persist node IDs and edges rather than an
unbounded nested aggregate when nodes have independent identity.

**Add explicitly bounded recursion.** A future mode could require a depth bound for fixtures and
validation while generating a normal terminating recursive codec. Its compatibility rules must
handle changes through strongly connected components without infinite diagnostics.

**Treat recursive support as a distinct research milestone.** It should not enter through a
generic “external type” loophole that claims structural coverage without traversing the cycle.


## 12. Existing History Makes Structural Adoption a Migration

### The convenience being lost

Even a better generated codec cannot simply replace a historical codec if bytes or decode policy
differ. For example, the old codec may omit `Nothing` while the new schema emits explicit `null`,
or it may use generic tagged-object names that differ from the proposed DSL tags.

### Improvements that keep the guarantee

**Import real goldens before declaring the shape.** The DSL declaration should be derived from the
historical wire contract, not from Haskell constructor spelling.

**Run shadow comparison.** During development, encode the same domain values with both codecs and
decode the historical corpus with the generated decoder. Report byte and semantic differences.

**Version rather than normalize silently.** If the desired new representation differs, add a new
event/codec version and explicit upcaster. Do not rewrite old event history or call a representational
change “formatting.”

**Retain legacy decoders only at the version boundary.** A historical decoder may remain as an
upcaster input. It must not remain a second authority for newly emitted values.


## Improvement Directions by Risk

### Low-risk ergonomics

These reduce work without changing the proof boundary:

- generated create-once binding skeletons and typed holes;
- `check --explain-bindings` with expected Haskell signatures;
- generator bindings and branch-coverage reports;
- shadow-codec comparison over existing goldens;
- compatibility vectors and remediation explanations;
- import-cycle and package-plan diagnostics;
- mapping skeletons for distinct public DTOs;
- representative codec benchmarks and encoder fusion.

### Medium-risk extensions

These can preserve guarantees but require new checked machinery:

- `GHC.Generics` or Template Haskell derivation of nominal bindings while wire policy stays in DSL;
- schema-bound external types where Keiro executes or validates the authoritative schema codec;
- first-class symbolic field projections generated from structural bindings;
- lifecycle-aware uninitialized registers instead of fake initial values;
- contract schema projections that generate distinct public DTOs and explicit mappings.

### Research-grade extensions

These should not be promised until their semantics and validation cost are proven:

- solver-visible bounded maps, membership, and element updates;
- bounded or strongly-connected recursive structural mappings;
- proof-carrying external codecs stronger than fixture testing;
- atomic multi-stream aggregate generations with a clear invariant and recovery model.


## A Proposal Test for Future Keiro Improvements

Before accepting an ergonomic improvement, answer all of the following.

1. **Authority:** Which artifact owns the wire schema, and does the executed codec come from it?
2. **Replay:** Can every forward register update be reconstructed only from emitted private events?
3. **Visibility:** Is every claimed guard/update represented in Keiki's symbolic language?
4. **Compatibility direction:** Does the report distinguish old-history reads, rolling deploys,
   snapshots, queues, and public consumers?
5. **Ownership:** Are private domain types and public DTOs still independently evolvable?
6. **Completeness:** What makes an omitted parser/diff/scaffold/harness case fail?
7. **Migration:** How are existing bytes, tags, defaults, and upcasters proven compatible?
8. **Recovery:** If generation, binding, or deployment fails halfway, can the old release continue
   safely and can the operation be retried?
9. **Performance:** Is any overhead measured, and can it be removed without introducing a second
   codec authority?
10. **Negative proof:** What mutation or negative fixture demonstrates that the guarantee would
    fail if the new machinery were incomplete?

If a proposal cannot answer one of these, it may still be useful as an explicitly opaque escape
hatch, but it should not be presented as a checked structural capability.


## Recommended Near-Term Experiments

The following experiments would improve Keiro's usability without weakening IR-1.

### Experiment A — Binding skeleton and direct codec generation

Use a three-field record, a five-arm tagged union, and a nested optional value. Generate the
binding skeleton plus direct Aeson encoder/decoder, then measure lines of hand-written code,
allocation, and throughput. The experiment succeeds if authors write only semantic construction
logic and explicit wire policy while generated bytes match pinned goldens.

### Experiment B — Historical shadow comparison

Point a prototype at Mori `DocInfo` goldens. Compare the current decoder/encoder with the proposed
structural codec across missing fields, explicit nulls, unknown fields, and every `DocLocation`
arm. The experiment succeeds only if differences are classified as exact parity or explicit
version/upcaster work.

### Experiment C — One solver-visible field projection

Add a minimal Keiki term for projecting one `Text` field through a generated witness. Implement
evaluation, validation, pretty diagnostics, and mutation tests before adding DSL syntax. The
experiment succeeds if the guard is fully visible to the existing validation pipeline and replay
behavior is unchanged.

### Experiment D — Usage-aware union-arm diff

Add one arm to a union used by a private event, a snapshot, and a public contract. Require the
report to produce three containing paths and distinct compatibility/rollout results. The
experiment succeeds if no universal “additive” label hides the public-consumer risk.


## Conclusion

IR-1's constraints are not free. Keiro becomes more explicit and, initially, more verbose. Opaque
types remain less analyzable, mapped values remain less symbolically expressive than ordinary
Haskell values, public messages need mapping code, and existing codecs require real migration
evidence.

The constraints are nevertheless well placed. They prohibit Keiro from claiming guarantees it
does not execute. The best path forward is to automate bindings, diagnostics, mappings, migration
comparison, and encoding—not to blur codec authority, hide Haskell functions behind checked DSL
syntax, or collapse private and public contracts. Keiro can recover much of the lost convenience
incrementally while keeping the event log, compatibility report, and symbolic model honest.
