# Exact conditional header prototype

Five allocation attribution trials with an external sequential TCP client and a running workflow header. Each request performs fresh schema verification and an exact PostgreSQL comparison of all 13 header fields. Unchanged rows reuse their canonical JSON value and bounded encoded bytes through a single-entry diagnostic seam. This is not an adopted production cache or a matched writer interference gate.

The conditional point session allocates about 19.7 kB per call; the conditional HTTP path about 53.2 kB, versus 101.7 kB for the ordinary header path. The remaining cost must still be assessed in matched writer runs; this does not establish the 5% gate or resource bounds for a general cache.

Timestamp images separate UTC days from seconds of day. Focused correctness tests compare every field, BC dates, distant dates with fractional seconds, missing/deleted rows and raw/escaped oversized values against the ordinary typed decoder. The first epoch-only prototype lost distant fractional precision and was replaced before this measurement. The default HTTP route remains unchanged.

`manifest.json` identifies the binary, retained driver and exact production-source patch against the parent commit. `summary.json` retains all five per-operation samples; the numbered JSON files retain raw RTS counters. Libraries use O1, the driver O2, GHC 9.12.4 and RTS `-N2 -T`. One TCP connection setup is amortized over each 1,000-request measurement. Client allocations are outside the server's RTS counters.
